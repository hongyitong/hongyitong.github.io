第8章 蒸馏推理模型以实现高效推理

Distilling reasoning models for efficient reasoning

本章涵盖： - 推理模型的硬蒸馏和软蒸馏 - 创建和准备教师生成的推理数据集 - 使用交叉熵损失训练和评估蒸馏后的学生模型

This chapter covers

  • Hard and soft distillation for reasoning models

  • Creating and preparing a teacher-generated reasoning dataset

  • Training and evaluating a distilled student model using cross-entropy loss

推理性能不仅可以通过推理时扩展和强化学习来提升，还可以通过蒸馏来提升。在蒸馏中，一个较小的学生模型在由较大教师模型生成的推理轨迹和答案上进行训练。如图 8.1 的概览所示，本章聚焦于这种训练时技术。

在讨论过程中的各个步骤之前，我们先总体介绍模型蒸馏。

图 8.1 本书涵盖主题的模型结构图。本章聚焦于蒸馏，即在一个较小的学生模型上训练较大教师模型生成的推理轨迹。

8.1 介绍用于推理任务的模型蒸馏

Introducing model distillation for reasoning tasks

模型蒸馏涉及在一个较小的 LLM（学生模型）上训练，使其学习由较大的 LLM（教师模型）产生的输出。对于推理模型而言，这些输出通常不仅包括最终答案，还包括通向答案的中间推理过程。

蒸馏之所以重要，是因为最强的推理模型往往体积过大、成本过高，难以直接使用。例如，DeepSeek-R1 拥有 6710 亿个参数。这种规模的系统开发和部署成本高昂，远超大多数从业者在本地硬件上运行的能力。DeepSeek-R1 团队通过蒸馏这个 6710 亿参数的教师模型，创建了较小的模型变体。本章将遵循相同的基本思路，但规模控制在本节书籍可行的范围内。

在本书中，我们有意识地使用小型模型，而不是从头开始训练一个非常大的 LLM，但本章的工作流程与大型模型是一致的。我们将使用一个更强的教师模型来生成推理过程，然后训练一个较小的学生模型来复现这些推理过程。在我们的设置中，这个蒸馏阶段所需的时间仅为大型模型的一小部分。我们的蒸馏训练在 DGX Spark 上大约需要 3 小时，使用约 15 GB 内存，而在同一硬件上，即使是第 6 章的几轮 GRPO 也需要大约 12 小时和 70 GB 内存。

蒸馏也可能比使用可验证奖励的强化学习（RLVR）训练小型模型更有效。例如，DeepSeek-R1 论文报告称，其较小的蒸馏变体优于仅使用强化学习训练的同类模型。在该设置中，最大的 DeepSeek-R1 模型（拥有 6710 亿参数）充当教师模型，生成用于训练较小学生模型的监督信号。

蒸馏主要有两种类型：硬蒸馏和软蒸馏。在硬蒸馏中，学生模型在教师模型生成的文本上进行训练，因此教师模型的 token 被当作目标。在软蒸馏中，学生模型通过最小化 KL 散度（一种衡量两个概率分布差异程度的指标）来学习匹配教师模型在词汇表上的概率分布。这两种方法如图 8.2 所示。

图 8.2 硬蒸馏让学生模型学习教师模型生成的 token；软蒸馏让学生模型学习教师模型的完整输出分布。

如图 8.2 所示，其中一种选择是纯硬蒸馏。在这里，我们仅使用教师生成的文本作为训练目标。如果你熟悉典型的 LLM 训练流程（在我之前的书籍《从零构建大语言模型》中有更详细的介绍），硬蒸馏就是在合成数据上进行的有监督微调。这也是 DeepSeek-R1 较小蒸馏变体所使用的设置。一个大型教师模型生成推理过程和答案，学生模型则通过微调来复现它们。根据 DeepSeek-R1 论文，对于小型模型，这种蒸馏方法可以获得比使用强化学习训练更高的准确率。硬蒸馏的主要实际优势在于，我们只需要访问教师模型生成的文本，而不需要其 logits。

第二种选择是纯软蒸馏。学生模型不仅要匹配教师模型选择的 token，还要学习匹配教师模型在整个词汇表上每个 token 的完整输出分布。这为学生模型提供了更丰富的信息，使其了解教师模型认为哪些备选 token 是合理的，但它在训练时需要访问教师模型的 logits 或 log 概率。

第三种选择是结合硬蒸馏和软蒸馏。这是经典的知識蒸馏设置，最早在计算机视觉领域流行起来，例如 Geoffrey Hinton、Oriol Vinyals 和 Jeff Dean 的论文《Distilling the Knowledge in a Neural Network》。在这种情况下，我们在教师模型的实际输出 token 上进行训练，同时鼓励学生模型匹配教师模型的完整分布。

在实践中，硬蒸馏在 LLM 中更为常见，部分原因是完整的教师 logits 通常无法获取。像 ChatGPT 或 Claude 这样的专有系统可能会暴露生成的文本，但它们通常不会暴露经典软蒸馏所需的完整词汇表分布。

警告  复用生成的文本进行蒸馏可能受到提供商特定使用政策的限制，包括 OpenAI 和 Anthropic 的服务条款，因此在使用此类输出进行训练之前，请仔细审查相关政策。

即使可以获取 logits，软蒸馏也比硬蒸馏更加繁琐。学生模型和教师模型通常需要相同的 tokenizer，以便它们的词汇表分布能够对齐，因此这种方法在同一模型族内更容易实现。同时，存储和使用长推理轨迹的完整 token 分布也昂贵得多。相比之下，存储纯文本输出既廉价又简单。

在本章中，我们将专注于 DeepSeek-R1 风格的硬蒸馏，因为它对大多数读者来说更为实用。本章讨论的步骤总结如图 8.3 所示。

图 8.3 本章涵盖蒸馏的四个主要步骤：(1) 蒸馏介绍与概述；(2) 数据集准备（步骤 2a-2c）；(3) 通过蒸馏进行训练（步骤 3a-3c）；以及 (4) 评估。

8.2 为推理蒸馏生成数据集

Generating a dataset for reasoning distillation

Building training examples

接下来，我们将原始的 dataset 条目转换为可供模型使用的训练样本。在高层面上，这意味着要一致地格式化提示和答案、进行 token 化，并将得到的 token ID 与提示长度一起存储。这个预处理阶段如图 8.7 所示。

图 8.7 通过理解 tokenizer、对样本进行 token 化以及过滤和拆分数据集，将加载的数据集转换为适合模型训练的格式。

这里的大部分工作都是直接的预处理。在 RLVR 章节中，我们在运行时进行了类似的准备，因为每个训练样本只被采样一次然后就被丢弃了。蒸馏则不同，我们通常会对相同的样本进行多个训练轮次的循环。因此，一次性格式化并 token 化整个数据集，存储处理后的样本，并在训练过程中复用它们，效率会更高。这也是为什么一旦收集了教师数据，蒸馏通常比 RLVR 更容易迭代的原因之一。

什么是训练轮次（epoch）？ 训练轮次，简称 epoch，是机器学习和深度学习中的标准术语。一个 epoch 是指对完整训练数据集的一次完整遍历。例如，如果我们训练三个 epoch，模型会看到每个训练样本三次，通常每次顺序不同。多个 epoch 通过反复查看同一数据帮助模型逐步改进。

8.6 计算训练损失和验证损失

Computing the training and validation losses

接下来，我们将实现交叉熵损失，这将作为之后实现训练循环时的训练信号。我们还将在验证集上复用相同的计算，以便在训练过程中监控进度。

如果你有深度学习背景，你可能已经熟悉分类任务中的交叉熵。这里的思路相同，只不过在每个位置上我们想要预测的目标类别是教师生成序列中的下一个 token。

我们可以将交叉熵损失直接与第 5 章和第 6 章中的 log 概率计算联系起来。如那里所述，log 概率衡量模型分配给正确下一个 token 的概率大小。log 概率越高，表示模型对正确 token 越有信心，log 概率越低则相反。复用之前章节中的"德国首都是柏林"示例，图 8.12 对此进行了回顾。

交叉熵就是图 8.12 中所示 token log 概率的负平均值。例如，如果 –16.6250 是 log 概率，那么负 log 概率是 16.6250，负平均 log 概率（即交叉熵）是 16.6250/5 = 3.325。注意分母为 5，因为序列中有 5 个目标预测的 log 概率被平均："capital"、"of"、"Germany"、"is"和"Berlin"。与 log 概率类似，交叉熵值越接近 0 越好，因为模型对正确目标 token 越有信心。

我们不会直接使用 sequence_logprob 返回的求和对数概率，而是将其在答案 token 数量上取平均。求和的对数概率随序列长度增长，因此在答案较短或较长的示例之间无法直接比较。通过除以答案 token 数量，我们得到每个 token 的量值，这与交叉熵损失所用的形式一致。我们可以用总序列长度减去 prompt_len 来计算答案 token 的数量。

8.9 推理模型的未来方向

Future directions for reasoning models

在结束本章之前，让我们讨论推理模型未来的发展方向。

在可预见的未来，基本模式将保持不变。例如，总体策略仍是开发更强的推理教师模型，收集高质量的推理轨迹，然后将其蒸馏到更小的学生模型中。

一个明确的方向是持续改进由 DeepSeek-R1 论文推广的训练方案，该方案既包括旗舰模型的 RLVR（第 6 章和第 7 章），也包括专注于计算效率的小型模型的蒸馏。

第二个方向是推理时间的优化。在实践中，推理模型不应总是产生相同长度的答案。某些任务受益于简短、直接的响应，而其他任务则受益于更详细、多步骤的推理。这为应用程序层的更自动化和灵活的推理扩展创造了空间，由上层系统决定何时需要简短答案、何时分配更多推理预算、以及何时提前停止。例如，OpenAI 在 2025 年推出 GPT-5 时实现了这样的系统，增加了一个"自动"模式来引导推理力度和推理轨迹生成长度。

第三个改进方向是 RLVR 的奖励生成。当前的工作仍然在很大程度上依赖于基于最终答案的奖励，尤其是在数学和代码领域。但检查中间推理步骤的过程奖励（而不仅仅是最终结果）可能提供更丰富的训练信号，并帮助模型学习更可靠的推理策略。例如，DeepSeek-Math-V2 论文（https://arxiv.org/abs/2511.22570）最近证明，在训练期间判断整个答案可以显著改善推理性能。

第四个方向是推理模型在更大的智能体应用中作为引擎的日益增长的角色，例如 OpenAI Codex、Claude Code 和 OpenClaw。在这些场景中，模型不仅需要解决简单的数学或编程问题，还需要规划、调用工具、从失败中恢复以及协调更长的工作流程。这自然将奖励设计推向了超越数学和代码正确性的范畴。我们可能需要以下方面的奖励：成功的工具使用、信息检索、策略合规等。这进而导致了多奖励训练，其中多个目标被一起优化，而不是依赖单一的正确答案分数。

蒸馏在此场景中可能仍然很重要，因为它提供了一种实用的方法，将这些更丰富的行为从更大、更昂贵的教师系统转移到更小的模型中，这些模型更易于部署，可以在本地运行，并且对用户更具成本效益。

个人注：

这段话所描述的趋势正在发生并部分实现，但它目前正处于快速落地和向纵深发展的阶段，而不是一个已经完全普及或到达终极形态的过去式。

我们可以从以下两个维度来看其实际进展：

  • 1. 推理模型作为智能体引擎（已初步实现并成为主流趋势）
    • 现状：像 Codex、Claude Code 以及各类高级 AI 编程和自动化工具，目前确实在大量使用具备强大推理与长程规划能力的大模型。这些模型不仅用于单点的文本或代码生成，还被赋予了调用终端、读写文件、多步规划以及在报错时自主修复（Debug）的能力。
  • 2. 超越单一正确答案的多奖励训练（正在攻坚的前沿方向）
    • 现状：传统的强化学习（如针对数学和代码的 RL）往往依赖二元的“对与错”奖励。而对于智能体（Agent）场景，单纯靠对错无法训练出优雅的工具使用习惯、信息检索效率或策略合规性。
    • 进展：目前，顶尖的 AI 实验室（如 OpenAI、Anthropic、DeepSeek 等）和学术界正在大力推进多目标奖励（Multi-reward）、过程奖励模型（PRM）以及基于人类/AI反馈的复杂对齐技术。将工具调用成功率、指令遵循度、安全性合规等多重指标纳入奖励函数进行联合优化，是当前大模型工程和研究中最核心的前沿方向之一。

总结：

这段话并不是纯粹的未来构想，而是当前大模型技术从“单纯的问答/解题”向“复杂智能体（Agent）应用”演进时的真实写照——它正在被各大厂商和研究者们逐步实现，并且是当前行业最炙手可热的演进方向。

8.10 结论

Conclusions

至此，本书的主要技术内容已完成。现在我们将看一些简短的指导，关于接下来可以尝试什么，如何跟上这个快速发展的领域，以及在哪里可以找到更多资料。

8.10.1 下一步做什么

What’s next

一个实用的下一步是开始组合本书中的方法，而不是将它们视为孤立的技巧。例如，你可以从强大的教师模型蒸馏出一个较小的模型，用 RLVR 继续训练，然后在部署时应用推理时间扩展方法，如自一致性或自我改进。运行这类比较通常是培养直觉的最快方式，以了解哪种方法在给定场景中最有帮助。

附录也是继续学习的好地方。它们涵盖了额外主题，如 LLM 架构细节、用于更高吞吐量的批处理执行以及替代评估方法。

最后，补充代码仓库（https://github.com/rasbt/reasoning-from-scratch）包含了额外的资料和独立脚本，这些脚本比 notebook 更适合长时间运行和更大规模的实验。

8.10.2 在快速发展的领域保持更新

Staying up to date in a fast-moving field

我希望这本书能让你更清晰地了解现代推理模型在实践中是如何工作的。

推理模型的研究发展迅速，具体的算法、数据集和最佳实践将继续变化，但本书中的核心思想将保持相关和有用。这些核心思想包括：仔细的模型评估、区分推理时间方法和训练时间方法，以及理解训练损失和奖励信号是如何计算的。

当新的方法出现时，将其映射回这些基本原理会有所帮助。许多新技术最好被理解为我们在此实现的构建块的变体或组合，即使周围的训练方案变得更加复杂。

在实践中，我推荐以下几个资源。首先，你可以浏览 arXiv 上最新的机器学习和 AI 论文（https://arxiv.org/list/cs.LG/recent），以及早发现新的训练和评估思路。但要注意，新论文的数量现已极为庞大，全面跟进几乎不可能，因此通常最好将 arXiv 视为扫描主题和有前景论文的方式，而不是试图阅读所有内容。

其次，阅读新发布模型的技术摘要和报告，因为它们通常包含关于提示约定、基准测试和局限性的最有用的细节。这些通常由开发者直接通过 Hugging Face 模型中心、公告博客文章和社交媒体分享。

第三，关注社交媒体平台 X 和社区（如 r/LocalLLaMA，https://www.reddit.com/r/LocalLLaMA/）中的从业者讨论，因为实现细节、复现工作和失败案例通常会在它们进入正式论文之前出现。

AI 助手或"深度研究"工具也可以用于监控这些来源并总结新进展，但它们最好作为过滤器，而不是替代阅读原始论文和模型卡。

总结

  • 蒸馏训练一个更小的学生 LLM，使其匹配更大教师 LLM 生成的输出。
  • 硬蒸馏通常比软蒸馏更实用，因为教师 logits 通常不可用，而教师文本输出存储和重用的成本低得多。
  • 我们使用 DeepSeek-R1 作为教师模型，Qwen3 0.6B 作为学生模型。
  • 蒸馏数据集由 12,000 个与 MATH-500 不重叠的 MATH 训练问题构建而成。
  • 每个训练样本将渲染后的 prompt 与教师推理轨迹和最终答案组合在一起，可选地通过 思考... response 标签分隔。
  • 为了提高效率，我们对数据集进行一次 token 化，按序列长度进行过滤，并在多个 epoch 中复用处理后的示例。
  • 训练目标是仅针对答案的交叉熵，等价于正确下一个 token 的负平均对数概率。
  • 蒸馏训练循环是一个标准的监督学习循环，包括每个 epoch 打乱训练示例、计算损失、反向传播、更新模型权重以及跟踪验证损失。
  • 验证损失是训练期间需要关注的主要信号。此外，建议定期在基准测试数据集上评估检查点。
