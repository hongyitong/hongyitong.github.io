《Build_a_Reasoning_Model》第1章理解推理模型

发表于 2026-09-07 分类于 书籍翻译

第 1 章 理解推理模型

Understanding reasoning models

本章涵盖

  • 对大型语言模型而言，"推理"意味着什么
  • 回顾 LLM 的传统预训练和后训练阶段
  • 介绍提升 LLM 推理能力的关键方法
  • 推理与模式匹配有何不同
  • 为什么我们应该从头构建推理模型

This chapter covers - What “reasoning” means for a large language model - Reviewing the conventional pretraining and post-training stages of LLMs - Introducing key approaches to improving reasoning abilities in LLMs - How reasoning differs from pattern matching - Why we should build reasoning models from scratch

欢迎来到大型语言模型（LLM）的下一个阶段：推理。LLM 已经改变了我们处理和生成文本的方式，但它们的成功很大程度上是由统计模式识别驱动的。推理方法的新进展现在使 LLM 能够处理更复杂的任务，例如解决逻辑谜题和多步数学问题。

此外，推理是使 AI 智能体变得实用的关键技术——例如当智能体需要将任务分解为步骤、使用工具并从错误中恢复时。推理 LLM 已经应用于像 OpenClaw 这样的智能体应用中。

在本书中，你将通过动手实践、代码优先的方法学习 LLM 推理方法的内在运作方式。我们将从一个预训练的 LLM 出发，逐步为其扩展推理能力。我们将从零开始亲自实现这些推理组件，以了解这些方法在实践中如何工作。

如果你对 LLM 本身是如何构建和训练的感到好奇，我之前由 Manning 出版的著作《Build a Large Language Model (From Scratch)》(http://mng.bz/orYv) 详细介绍了这些基础，但并非跟随本书的先决条件。

即使你只是粗略了解 LLM 的构建方式，到本书结束时，你也会理解推理模型的工作原理，并能够设计、原型化和评估改进 LLM 推理的主要方法。

在处理推理模型时，关键是要知道如何在数学等任务上自动检查答案是否正确，以及如何将通用模型转化为更小的推理模型。我们将在全书中使用数学示例，因为它们易于自动检查，但你不需要高级数学知识来跟随学习。理解推理方法是本书的核心重点。

本书以实际应用和解释为重点，面向 LLM 工程师、机器学习研究人员、应用科学家和软件开发者。理解推理模型的设置方式将帮助我们判断何时标准 LLM 已足够，何时额外的推理机制值得增加的复杂性、成本和延迟。它还帮助我们设计更好的评估、调试多步任务中的失败，并将推理技术适配到实际产品和研究工作流中。

1.1 在 LLM 语境下定义推理

Defining reasoning in the context of LLMs

在本书中，我从实用的工程角度而非哲学角度使用"推理"一词。在 LLM 语境下，推理指的是模型在生成最终答案之前产生中间步骤的过程。

这些中间步骤可能表现为可见的逐步推理过程，也可能被包裹在特殊的标记中（如 thinking.../think）并对用户隐藏。无论哪种情况，核心思想都是一样的——模型被鼓励或训练使用 token 进行中间解题步骤，而不是直接跳到结论。

相应地，我使用"推理模型"来指代一个通过训练或提示技术得到改进、能够产生此类中间步骤的 LLM，这通常能提高其在复杂任务（如编程、逻辑谜题和数学问题）上的准确性。

在我们进入本书的编程部分之前，我会简要讨论改进这些推理行为的主要技术，以及它们与模式匹配和逻辑推理之间的关系。这将为后续讨论奠定基础，包括 LLM 当前是如何构建的、它们如何处理推理任务，以及它们的优点与局限。

思维链（CoT）

这种生成中间步骤的方式通常被称为思维链（Chain-of-Thought，CoT）。研究人员和工程师常说，模型"一步一步地思考"问题，这意味着它将自己的中间推理过程显式呈现出来，使其更易于理解。在本书中，我在这一常见的工程意义上使用"推理"和"思考"这两个词。这并不意味着 LLM 真正像人类那样进行推理或思考。

图 1.1 展示了一个传统 LLM 如何生成用户问题的答案。传统 LLM 可能不会显示它是如何得出答案的，虽然答案可能是正确的，但这无助于用户理解其背后的过程。

图 1.1 一个简化的示意图，展示了一个传统的、非推理型 LLM 可能如何用一个简短答案来回应问题。

图 1.2 展示了一个 LLM 中的多步骤（CoT）推理的简单示例。LLM 生成的中间推理步骤看起来非常像一个人在自言自语地表达内心思考。这些方法（以及由此产生的推理过程）在多大程度上模仿了人类推理，仍然是一个开放的研究问题，本书不试图回答这个问题。

图 1.2 一个简化的示意图，展示了一个推理型 LLM 如何使用思维链来处理多步骤推理任务。模型不是仅仅回忆一个事实，而是结合多个中间推理步骤来得出正确的结论。根据具体实现，中间推理步骤可能会或不会显示给用户。

虽然图 1.2 是思维链推理的一个典型示例，但需要强调的是，LLM 推理与传统的、确定性的推理不同。例如，一个符号逻辑引擎或定理证明器遵循严格的、基于规则的步骤，保证一致性和正确性。它就像按照食谱操作——每一步都是固定的，且每次都会产生相同的结果。如果你严格按照步骤操作，你总是会得到同样的菜肴。

与符号逻辑引擎不同，LLM 以自回归方式生成推理结果，这意味着它基于训练数据中的统计模式逐个预测 token。因此，LLM 的"推理步骤"并不保证在逻辑上是合理的，即使它们看起来令人信服。

本书专注于解释和实现提升 LLM 推理能力的基础技术，使 LLM 更擅长处理复杂任务。我希望通过亲手实践这些方法，你能更好地理解并改进正在开发的推理方法，甚至可能探索这些方法与人类推理之间的异同。

LLM 推理 vs. 人类推理

LLM 中的推理过程可能在表面上与人类思考相似，特别是在中间步骤的表达方式上。但重要的是要认识到一个关键区别：人类可以通过有意识地应用逻辑规则或基于内在的世界模型进行推理来参与确定性推理。这里的"确定性"意味着，如果我们从相同的事实出发并遵循相同的步骤，我们总会得到相同的结论。相比之下，当前的 LLM 推理是概率性的，这意味着它基于训练数据中的统计模式逐个生成 token，而不保证逻辑一致性。

人类通常通过有意识地操纵概念、直观理解抽象关系或从少量示例中进行归纳来推理。相比之下，LLM 则是通过从海量文本中拾取模式来运作，而不是依靠内置的推理规则或任何形式的意识思维。

简而言之，虽然经过推理增强的 LLM 的输出可能看起来像人类的输出，但其底层机制存在本质差异，并且仍是一个活跃的探索领域。

1.2 理解标准的 LLM 训练流水线

Understanding the standard LLM training pipeline

让我们简要地看一下传统（非推理）LLM 通常是如何训练的，这样我们就能理解它们的局限性所在。这一背景知识也将帮助我们后续讨论模式匹配与逻辑推理之间的区别。

在应用任何特定的推理方法之前，传统的 LLM 训练通常分为两个阶段：预训练和后训练，如图 1.3 所示。一些近期的论文还在这两个阶段之间区分了一个"中期训练"阶段，例如在代码、数学或长上下文数据上继续训练模型，但为简化术语，本书将这一阶段归入预训练。

图 1.3 典型 LLM 训练流水线概览。过程从随机权重初始化的模型开始，然后在海量文本数据上进行预训练，通过预测下一个 token 来学习语言模式。后训练阶段通过指令微调和偏好微调来精炼模型，使 LLM 更好地遵循人类指令并与人类偏好对齐。

在典型 LLM 训练流水线的预训练阶段，LLM 在海量的无标签文本上进行训练，通常达到许多 TB 的数据或数万亿个 token，包括书籍、网页、研究文章等众多来源。LLM 的预训练目标是学习预测这些文本中的下一个词（即下一个 token）。

词与 token

Token 是语言模型处理的文本小单元。一个 token 可以是一个完整的词、词的一部分，甚至是标点符号，具体取决于分词器对文本的切分方式。

例如，句子"An LLM can be useful."可能会被一个常见分词器分割为 "An"、" L"、"LM"、" can"、" be"、" useful"、"." 等 token。这些 token 随后被转换为模型可以处理的数值 ID。

分词器本身不是 LLM 的一部分，但它仍然是 LLM 文本处理和生成流程中的关键组成部分。我们将在下一章了解分词的工作原理。

LLM 在海量数据集上预训练后变得非常强大——这通常涉及数 TB 的文本（相当于数万亿个 token），需要数千块 GPU 运行数月，成本可达数百万美元。这里说的"强大"是指 LLM 开始生成与人类写作高度相似的文本。在某种程度上，预训练的 LLM 也开始展现出所谓的涌现属性，这意味着它们可以执行未被明确训练的任务，包括翻译和代码生成。

这些预训练模型作为后训练阶段的基础模型。后训练阶段使用两种关键技术：监督微调（文献中常缩写为 SFT，也称为指令微调）和偏好微调，以教会 LLM 响应用户查询。

如图 1.4 所示，指令微调提升了 LLM 在个人助理类任务上的能力，如问答、摘要、文本翻译等。偏好微调阶段则进一步精炼这些能力。顾名思义，偏好微调有助于定制响应以满足用户偏好。有些读者可能熟悉"基于人类反馈的强化学习"（RLHF）这个术语，它是实现偏好微调的一种特定技术。

简而言之，我们可以把预训练视为"原始语言预测"（通过下一个 token 预测），它赋予 LLM 产生连贯文本的基本属性和能力。后训练阶段则通过指令微调提升 LLM 的任务理解能力，并通过偏好微调使其根据偏好风格来精炼生成答案。

值得注意的是，即使经过指令微调的模型也还不是一个"聊天机器人"。聊天界面增加了另一层，用于在交互式的多轮对话环境中引导模型的响应。这通常涉及系统提示词、对话历史管理以及其他编排工作（附录 G 中实现了一个示例）。

图 1.4 语言模型在不同训练阶段的示例回答。提示要求总结睡眠与健康之间的关系。预训练 LLM 生成了相关但不聚焦的回答，没有直接遵循指令。指令微调 LLM 生成了简洁准确的摘要，与提示对齐。偏好微调 LLM 通过使用友好的语气和引人入胜的语言进一步改进了回答，使答案更亲切、更以用户为中心。

注： 这些预训练和后训练阶段在我的另一本书《Build a Large Language Model (From Scratch)》（Manning 出版社，http://mng.bz/orYv）中有详细介绍。你现在正在读的这本书并不要求深入了解那些阶段。在这里，我们将直接加载一个已经完成昂贵的预训练和后训练阶段的模型，以便专注于推理模型特有的方法。

1.3 通过训练和推理技术改进 LLM 推理

Improving LLM reasoning with training and inference techniques

LLM 语境下的推理，随着 OpenAI 于 2024 年 9 月 12 日在 ChatGPT 中宣布 o1 模型而进入公众视野。在公告文章中，OpenAI 写道："我们开发了一系列新的 AI 模型，旨在响应之前花更多时间思考"（https://openai.com/index/introducing-openai-o1-preview/）。此外，OpenAI 还写道："这些增强的推理能力在解决科学、编程、数学等领域的复杂问题时可能特别有用。"

几个月后，即 2025 年 1 月，DeepSeek 发布了 DeepSeek-R1 模型和技术报告，其中详细介绍了开发推理模型的训练方法（https://arxiv.org/abs/2501.12948）。这引起了巨大反响，因为该公司不仅免费公开了一个性能可与专有的 o1 模型媲美甚至超越它的模型，而且还分享了训练这类模型的蓝图。在本书中，我们将通过从头实现类似的方法来了解用于开发推理模型的方法论是如何运作的。

开发和改进 LLM 推理能力的不同方法可以分为三大类，如图 1.5 所示。这些方法通常应用于已经完成传统预训练和后训练阶段（包括指令微调和偏好微调）的 LLM。

图 1.5 提升 LLM 推理能力常用的三种方法：推理计算扩展、强化学习和蒸馏。这些方法通常应用于传统训练阶段（初始模型训练、预训练、以及带指令微调和偏好微调的后训练)之后，但推理技术也可以应用于预训练的基础模型。

我们将在全书中更详细地审视这些常见方法：

  • 推理时计算扩展（也常被称为推理计算扩展、测试时扩展等）包括在推理时（即用户提示模型时）提升模型推理能力的方法，而无需训练或修改底层模型权重。其核心思想是用增加的计算资源换取更高的性能，通过思维链推理和各种采样程序等技术，即使是固定的模型也能变得更强大。这将是第 4 章和第 5 章的重点。

  • 强化学习（RL） 指的是通过鼓励模型采取能获得高奖励信号的行为来改进模型推理能力的训练方法。这些奖励可以是宽泛的（如任务成功或启发式分数），也可以是狭义定义且可验证的（如数学问题或编程任务中的正确答案）。

    与推理时计算扩展不同（后者可以在不修改模型的情况下提高推理性能），RL 在训练期间更新模型权重。这使得模型能够根据从环境收到的反馈，通过试错来学习和精炼推理策略。我们将在第 6 章和第 7 章中更详细地探讨 RL。

  • 蒸馏 涉及将更强大模型习得的复杂推理模式转移到更小或更高效的模型中。在 LLM 语境下，这通常意味着使用由更大、更强大的模型生成的高质量标注指令数据集进行监督微调（SFT）。这一技术在 LLM 文献中通常被称为知识蒸馏或简称为蒸馏。需要注意的是，这与传统深度学习中的知识蒸馏略有不同——在传统知识蒸馏中，较小的（"学生"）模型通常同时从较大（"教师"）模型的输出和 logits 中学习。这一主题在第 8 章中进一步讨论。

用于推理的强化学习与偏好微调

在开发推理模型的语境下，有必要区分强化学习（RL）方法和基于人类反馈的强化学习（RLHF）——后者是在开发传统 LLM 时用于偏好微调的方法。两者都使用相同的底层过程（RL），但主要区别在于奖励的获取和验证方式（RLHF 使用人工判断，而推理 RL 使用自动验证器或环境反馈）。

RLHF 使用显式的人工评估或对模型输出的排序作为奖励信号，直接引导模型趋向人类偏好的行为。相比之下，推理模型语境下的 RL 通常依赖自动化或基于环境的奖励信号，这些信号可能更客观，但与人类偏好的对齐程度较低。例如，推理模型开发流水线中的 RL 可能通过提供正确性奖励来训练模型擅长数学证明，而 RLHF 则涉及让人类评估者对各种回答进行排序，以鼓励输出更符合人类标准和主观偏好。

1.4 模式匹配 vs. 逻辑推理

Pattern matching vs. logical reasoning

在预训练期间，LLM 接触海量文本，通过学习识别和再现数据中的统计关联来预测下一个 token。这一过程使模型能够生成流畅且连贯的文本，但其基础是学习到的统计规律，而非显式的规则或保证正确的逻辑推理。

LLM 通过生成与训练中见过的模式统计一致的文本来响应用户提示。这包括许多看起来像逻辑推理的前提到结论的模式。关键区别在于，模型并不显式地表示前提并应用形式规则，而是根据训练数据中相似示例来预测可能的延续。

考虑以下示例：

德国的首都是…… 柏林。

一个 LLM 给出"柏林"这个答案并不是通过逻辑推导，而是回忆从训练数据中学到的强统计关联。这种行为反映的是我们所说的模式匹配，即模型基于学习到的相关性而非应用结构化推理步骤来完成文本。

但是，那些超越模式识别、正确答案取决于从给定事实中得出结论的任务呢？这就引出了另一种能力：逻辑推理。

逻辑推理涉及使用规则系统地得出结论。与模式匹配不同，它依赖于中间推理步骤以及基于形式关系识别矛盾或推导含义的能力。

考虑以下提示作为示例：

所有鸟都能飞。企鹅是一种鸟。企鹅会飞吗？

有两种评估方式。

首先，在封闭世界（仅限提示内容）设定下，给定提示中的两个前提（主张或假设），有效的答案是"是的，企鹅会飞。"

其次，在开放世界（包含背景知识）设定下，如果我们考虑提示中未包含的知识（例如企鹅不会飞），这个外部事实与从前提推导出的结论产生冲突，如图 1.6 所示。一个推理系统应该注意到这种不一致性，并要求澄清或弱化第一个陈述（例如，"大多数鸟都能飞，但企鹅等例外情况除外"）。相比之下，一个统计（模式匹配）LLM 不会显式跟踪矛盾，而是基于学习到的文本分布进行预测。例如，如果"所有鸟都能飞"这类信息在训练数据中被强烈强化，模型可能会自信地回答"是的，企鹅会飞。"

图 1.6 矛盾的前提导致逻辑不一致。从"所有鸟都能飞"和"企鹅是一种鸟"出发，我们推断出"企鹅会飞"。这一结论与已知事实"企鹅不会飞"相冲突，从而产生矛盾。

在下一节中，我们将看到 LLM 如何处理这个"所有鸟都能飞……"的提示。

逻辑推理与基于规则的系统

为什么显式的基于规则的系统不那么流行？基于规则的系统在 80 年代和 90 年代被广泛应用于医疗诊断、法律判决和工程领域。它们现在仍然用于关键领域（医学、法律、航空航天），这些领域通常需要显式的推理和透明的决策过程。但它们难以实施，因为很大程度上依赖人工设计的启发式规则。（启发式规则是简单的决策规则，能快速给出足够好的答案，但不保证最优。）相比之下，深度神经网络（包括 LLM）不实现手工编写的规则；它们从数据中学习决策模式，并且在大规模训练时可以非常灵活。

1.5 在没有显式规则的情况下模拟推理

Simulating reasoning without explicit rules

我们看到了矛盾的前提如何导致逻辑不一致。传统 LLM 不会显式跟踪矛盾，而是基于学习到的文本分布生成响应。

图 1.7 展示了 OpenAI ChatGPT 中一个未经推理增强的 LLM（如 GPT-4o）如何回应上一节讨论的"所有鸟都能飞……"提示。如图所示，GPT-4o 似乎给出了正确的回答，尽管它不被视为推理模型（不同于 OpenAI 的其他产品，如 o1、o3、o4-mini 以及更近期的 GPT-5，后者是明确使用推理方法论开发的）。

图 1.7 一个示意性示例，展示语言模型（ChatGPT 中的 GPT-4o）如何"推理"一个矛盾前提。

那么 4o 模型是如何生成答案的？这是否意味着 GPT-4o 显式地进行逻辑推理？不，不一定。至少，GPT-4o 在熟悉的语境中非常擅长模拟逻辑推理。

GPT-4o 并没有实现显式的矛盾检查，而是基于概率加权的模式生成答案。这种方法效果足够好，前提是训练数据中包含许多纠正了这一矛盾的实例（例如，"企鹅不会飞"这类文本），使模型学习到"企鹅"和"不会飞"之间的统计关联。换句话说，模型隐含地识别出矛盾，是因为它在训练中频繁遇到这个确切的推理场景。这种效果极大地依赖于从训练数据中大量接触类推理模式而建立的统计关联。因此，即使传统 LLM 看起来像图 1.7 那样进行逻辑推理，它也不是在执行显式的、基于规则的逻辑，而是利用其海量训练数据中的模式。

尽管如此，GPT-4o 在此处的成功很好地说明了当在大规模数据上训练时，隐式模式匹配可以变得多么强大。这些基于模式的推理模型通常在以下几种场景中会遇到困难：

  • 当逻辑场景是新颖的（训练数据中未曾见过）

  • 当推理复杂度高时，涉及复杂、多步骤的逻辑关系

逻辑推理与当前可用的推理模型

虽然 GPT-4o 没有被正式标记为推理模型，但 OpenAI 提供多个专用的推理模型，包括 o1、o3、o4-mini 和 GPT-5。此外，其他公司也在开发具有显式推理能力的 LLM。在撰写本文时，流行的例子包括 Anthropic 的 Claude 4、xAI 的 Grok 4、Google 的 Gemini 2.5、DeepSeek 的 R1、阿里巴巴的 Qwen3 等等。这些模型所采用的技术正是本书的重点。我们将看到，这并不需要实现基于规则的推理流水线；相反，LLM 将通过修改后的推理和训练方法来学习或改进其推理能力。

我们可以说，LLM 通过学习到的模式来模拟逻辑推理。我们可以通过特定的推理方法（包括推理计算扩展和后训练策略如强化学习）进一步改进这一点，但 LLM 在内部并没有显式地执行任何基于规则的逻辑。

此外，LLM 存在于一个光谱上。即使在专门的推理模型（如 OpenAI 的 o1 和 DeepSeek-R1）出现之前，LLM 也能模拟推理行为。这些模型展现的行为符合本章第 1.1 节中对推理的早期定义，即生成中间步骤后再产生最终答案。我们现在明确标注为"推理模型"的东西，本质上是这种能力的更精炼版本。这些改进的推理能力是通过使用特定的推理计算扩展技术（第 4 章和第 5 章讨论）和目标性的后训练方法（如第 6 章和第 7 章讨论的强化学习）来实现的，这些方法旨在改进和强化类推理行为。

1.6 为什么要从头构建推理模型？

Why build reasoning models from scratch?

自 2025 年 1 月 DeepSeek-R1 发布以来，提升 LLM 的推理能力已成为 AI 领域最热门的话题之一，这并非没有道理。更强的推理能力使 LLM 能够解决更复杂的问题，从而在用户关心的各种任务上变得更加出色。

这种转变也反映在 OpenAI CEO 于 2025 年 2 月 12 日的一份声明中：

我们接下来将发布 GPT-4.5（我们内部称为 Orion 的模型），作为我们最后一个非思维链模型。在那之后，我们的首要目标之一是将 o 系列模型和 GPT 系列模型统一起来，创建能够使用我们所有工具、知道何时应该长时间思考或不需要思考、并且总体上在广泛任务中都有用的系统。

上述引文突显了领先 LLM 提供商向推理模型的重大转变。这里的"思维链"指的是一种提示技术，它引导语言模型逐步推理以提升其推理能力；我们将在第 4 章和第 5 章中详细介绍。

同样值得注意的是"知道何时应该长时间思考或不需要思考"这一提法。这暗示了一个重要的设计考量：推理并非总是必要或可取的。例如，推理模型是为复杂任务而设计的，如解谜、高级数学问题和具有挑战性的编程任务。它们也常在智能体系统中发挥作用，特别是任务分解、规划和选择使用哪些工具时。而对于摘要、翻译或基于知识的问题回答等简单任务，推理模型并非必需。事实上，对一切任务都使用推理模型可能既低效又昂贵。例如，它们通常使用起来更昂贵、更冗长，有时因"过度思考"而更容易出错。这里适用的原则是：对任务使用正确的工具（或正确的 LLM 类型）。

推理模型通常比非推理模型更昂贵，原因有二。首先，它们倾向于产生更长的输出，因为包含了解释如何推导出答案的中间步骤。如图 1.8 所示，LLM 一次生成一个 token，每个 token 都需要一次完整的前向传播。如果推理模型的答案长度翻倍，那么生成过程大约需要两倍的前向传播次数，从而增加计算成本。

图 1.8 LLM 中逐 token 的生成过程。每一步，LLM 接受到目前为止生成的完整序列，并预测下一个 token（根据分词器，它可能表示一个词、子词或标点符号）。新生成的 token 被附加到序列中，并用作下一步的输入。这种迭代解码过程在标准语言模型和推理模型中都使用。

其次，许多推理工作流需要针对单个任务多次运行模型，例如采样多个候选解决方案、调用工具或运行验证器。这些额外调用将处理的 token 总数成倍增加，并进一步增加了超出图 1.8 所示单次调用的成本。

这正是从头实现这些模型和方法的意义所在。这是理解它们工作原理的最佳方式之一。如果我们理解了 LLM 和推理模型的工作原理，我们就能更好地理解这些权衡。

总结

  • 传统 LLM 训练经过几个阶段：

    • 预训练，模型在海量文本上学习语言模式
    • 指令微调，改进模型对用户提示的响应
    • 偏好微调，使模型输出与人类偏好对齐

  • 推理方法是在传统 LLM 之上应用的。

  • LLM 中的推理指的是改进模型，使其在产生最终答案之前显式地生成中间步骤（思维链），这通常能提高多步骤任务的准确性。

  • LLM 中的推理不同于基于规则的推理，而且很可能也不同于人类推理。目前共识是，LLM 中的推理依赖于统计模式匹配。

  • LLM 中的模式匹配纯粹依赖于从数据中学习到的统计关联，这使得模型能够生成流畅的文本，但缺乏显式的逻辑推理能力。

  • 提升 LLM 推理能力可以通过以下几种方式实现：

    • 推理时计算扩展：在不重新训练的情况下改进推理（例如思维链提示）
    • 强化学习：使用奖励信号显式训练模型
    • 监督微调和蒸馏：使用更强推理模型的示例

  • 从头构建推理模型可以提供关于 LLM 能力、局限性和计算权衡的实际洞察。
