第4章 通过推理时缩放提升推理能力

Introduction to inference-time scaling

本章涵盖

  • 提示 LLM 解释其推理过程以提高答案准确率
  • 修改文本生成函数以生成多样化的响应
  • 通过对多个响应进行采样来提高推理可靠性

This chapter covers

  • Prompting an LLM to explain its reasoning to improve answer accuracy

  • Modifying the text generation function to produce diverse responses

  • Improving reasoning reliability by sampling multiple responses

无需重新训练或修改模型本身，即可提升推理性能和答案准确率。如图 4.1 的概览所示，本章涵盖两种推理时缩放方法。这些方法在推理阶段（即模型生成文本时）起作用。正如你在本章后续部分将看到的，这两种方法都能将前几章中使用的基础模型的准确率提升一倍以上。

在讨论图 4.1 中展示的推理方法之前，我们首先了解什么是推理时缩放。

图 4.1 本书涵盖主题的模型。 本章重点讨论推理时缩放技术，这些技术无需额外训练即可提升推理能力（阶段 3）。具体来说，它扩展了文本生成函数并实现了一种基于投票的方法来提高答案准确率。下一章将介绍另一种推理时缩放方法，即模型迭代地改进自己的答案。

4.1 推理时扩展简介

Introduction to inference-time scaling

提升推理能力主要有两种策略：

  • 增加训练计算量(Increasing training compute)
  • 增加推理计算量（也称为推理时扩展或测试时扩展）( Increasing inference compute (also known as inference-time scaling or test-time scaling)

注意 在机器学习和人工智能中，"计算量"指训练或运行模型所需的计算资源。

这两种方法如图 4.2 所示。从图中看，似乎既可以通过增加训练时计算量，也可以通过增加推理时计算量来提升推理能力。实际上，LLM 通常通过结合大量训练时计算（未来章节的主题）和增加推理时计算（本章的主题）来提升推理能力。

推理时计算扩展（也称为推理时扩展或测试时计算扩展）是指在模型完成训练后，在答案生成阶段增加计算量，以提升响应质量。我们不改变模型的权重，而是让训练好的模型在每个问题上投入更多计算工作，例如生成更多 token 并"思考"更长时间、采样多个答案，或逐步迭代优化答案。

个人注：

“生成更多 token 并‘思考’更长时间”是指在模型输出最终答案之前，通过延长内部的文本生成过程，让模型进行类似人类的隐式推理、自我纠错或多步规划。

具体来说，在传统的问答中，大模型通常是“直觉式”地直接吐出答案（即从前往后顺着生成）。而在推理时计算扩展中（例如类似 OpenAI o1、DeepSeek-R1 等带有长思考过程的模型），其具体表现和实现方式通常有：

  • 输出中间思考过程（Chain of Thought）：模型在回答前，会先写下一大串分析、拆解、假设和验证的文本（通常放在 <think> 标签内）。这部分文字也是由 token 组成的，模型在这个过程中自己和自己“对话”，把复杂问题拆解成一步步小步骤。
  • 多步试错与自我修正：在“思考”的 Token 序列中，模型可能会写下诸如“等等，这样算好像不对，应该是……”或者“换一种方法验证一下”的内容。通过生成这些额外的 token，模型有机会在输出最终结论前纠正半路产生的错误。
  • 计算资源的横向或纵向换取质量：传统的计算量主要在“训练阶段”。而这种方式将算力挪到了“推理阶段”——对于一个困难的数学或编程题，它宁可多花几秒钟、多生成几千个中间思考的 token，来换取最终答案极高的准确率。

在本节中，我们将重点讨论三种实用且基础的推理时技术（如图 4.3 所示）：

  • 方法 1：扩展思维链响应，引导模型解释其推理过程。这一简单技术能显著提升准确率。
  • 方法 2：通过自一致性进行并行采样，即模型生成多个响应并选择最频繁的那个。
  • 方法 3：迭代自精炼，即模型在多步骤中审查并改进自己的推理和答案。

这些方法属于推理时扩展的范畴，因为它们促使模型生成更多 token，从而增加了推理过程中的计算需求。它们在提升准确率的同时增加了推理成本，这是推理时扩展技术的共同特点。本章我们将讨论前两种方法；第三种方法将在第 5 章介绍。

图 4.2 对比推理时扩展（本章讨论）和训练时扩展（第 6-8 章讨论）。两种方法都通过使用更多计算量来提升准确率，但推理时扩展是在推理过程中动态进行，无需改变模型的权重参数。该图灵感来源于 OpenAI 介绍其首个推理模型的文章（https://openai.com/index/learning-to-reason-with-llms/）。

图 4.3 三种提升推理能力的推理时方法。第一种方法修改提示词以鼓励逐步推理，第二种方法采样多个答案并选择最频繁的那个。这两种方法将在本章讨论。第三种方法让模型迭代优化自身响应，将在下一章介绍。

第一种方法通过提示模型解释其推理过程来提升答案准确率，这是一种简单却极其有效的方法。

第二种方法对同一输入采样多个响应并选择最频繁的那个。我们将通过扩展前一章引入的文本生成函数，实现一种基于投票的推理时扩展技术——自一致性。

总的来说，我评估了超过十种不同的推理时扩展技术，进行了数千次实验。我之所以选择图 4.3 中展示的三种方法，是因为它们兼具三个理想特性：它们在本书所用模型上能提升准确率，代表了推理时扩展的主要实用范式，并且实现起来足够简单，无需过多额外机制。它们还涵盖了两种主要模式：生成更长的响应和生成多个响应。

包含推理和解释的较长响应（方法 1 和 3）是我们通常期望从推理模型中获得的。并行采样（方法 2）也广泛应用于生产系统，例如 Claude 4（详见 2025 年 5 月 Claude 4 发布介绍：https://www.anthropic.com/news/claude-4）。

4.3 使用思维链提示生成更好的响应

Generating better responses with chain-of-thought prompting

我们已经加载了预训练的基础模型并设置好了文本生成函数；现在我们将专注于通过所谓的思维链提示来改进模型输出。这种提示技术经典、简单且有效。它修改输入提示词，鼓励 LLM 生成解释或思维链（也称为推理链），如图 4.4 所示。

实现思维链提示的最简单方法是在提示词末尾附加一条额外指令，要求模型逐步推理。表述方式有多种。例如，该主题的原始论文使用了 "Let's think step by step."（https://arxiv.org/abs/2205.11916），但不同的表述方式可能在不同模型和任务上效果各异。这里我们使用 "Explain step by step."，因为它在我的本章实验中效果良好，且能保持示例简洁：

图 4.4 我们的第一种推理时方法——思维链提示，通过修改提示词鼓励模型在给出最终答案之前，逐步解释其推理过程。

现在响应如下：

如你所见，模型现在写出了冗长的逐步解释，并在此情况下得出了正确答案。

这个简单的思维链提示很好地展示了推理时扩展的权衡。虽然模型现在正确回答了问题，但消耗的 token 数量远多于之前。如第 2 章所述，LLM 逐个 token 生成文本，每增加一个 token 都需要一次前向传播。因此，这些中间推理步骤不仅使答案变得更长，还直接增加了延迟、计算成本和通常的 API 成本。

注意，虽然本例中模型生成了正确答案，但并非所有问题都能从思维链提示中受益。对于简单问题，它有时甚至会降低模型性能，因为模型可能生成错误解释并误导自身。这种现象称为"过度思考"。

最后，并非所有模型都能从"Explain step by step"（或类似）指令中受益。本例中我们使用的是一个简单的基础模型，它并不总是生成解释，因此思维链提示有所帮助。而经过训练的推理模型，如我们在前一章中使用的 Qwen3 模型的"推理"变体，已经能在生成响应时附带解释，因此不需要也不会从这类思维链提示中受益。

思维链为何能提升准确率

思维链提示要求模型写出通向最终答案的中间步骤。这在两个实用方面有所帮助。

首先，逐步推理给了模型更多自我纠正的机会。

其次，逐步推理与许多训练示例的写法相匹配。例如，大型数学和逻辑数据集通常包含详细的求解过程，因此要求模型输出思维链有助于将其引导至已经学习过的模式。

同时，思维链推理并不能保证正确性。它仍然可能产生错误的推理，对于非常简单的问题，甚至可能引入不必要的步骤，导致更多错误。换句话说，思维链可以提升许多推理任务的准确率，但并非普遍有益。

总体而言，思维链提示并未为模型提供新知识，而是改变了模型使用已有知识的方式。通常，这种转变可以带来更可靠的答案，尤其是在数学、代码、逻辑及其他多步骤问题上。

4.4 使用温度缩放控制输出多样性

Controlling output diversity with temperature scaling

上一节通过思维链提示扩展模型答案，初步介绍了推理时扩展。思维链提示可以被视为一种顺序技术，因为它增加了下一个 token 预测的步数。

在本章剩余部分，我们将实现一种自一致性技术（也称为自一致性采样），它能生成多个答案，如图 4.5 所示。该技术在 Google Research 的论文《Self-Consistency Improves Chain of Thought Reasoning in Language Models》（https://arxiv.org/abs/2203.11171）中得到了正式描述。

图 4.5 自一致性采样——我们的第二种推理时方法——生成多个答案并选择最频繁的那个。该方法依赖于温度缩放，后者影响模型采样下一个 token 的方式。

由于使用该技术生成的多个答案彼此独立，因此可以通过并行采样实现（如果具备多 GPU 等必要资源），这不会增加用户等待答案的时间。（思维链提示可以与这种技术结合使用，具体稍后讨论。）

在实现自一致性采样（图 4.5 中的第 5 步）之前，我们首先需要扩展文本生成函数，使其能够对同一提示词生成不同的答案。为此，我们将实现两种允许模型采样不同响应的技术：温度缩放（第 3 步）和 top-p 过滤（第 4 步）。

温度缩放是本节的焦点；它将是本章后续内容中控制输出多样性的关键手段之一，并且构成了随之而来的 top-p 过滤方法的基础。不过，我们首先来看 LLM 如何采样下一个 token。这些底层的采样控制看似过于技术性，但正是它们让我们能够为自一致性采样生成多样化的候选答案。

4.4.2 通过温度参数重新缩放 token 分数（logits）

Rescaling token scores (logits) via a temperature parameter

现在你已经了解了模型如何选择下一个 token，我们可以引入温度的概念。温度，或者更准确地说，温度参数，对 logits 进行重新缩放，使对应的概率分布变得更尖锐或更平坦，从而影响下一个 token 的选择方式。

如图 4.8 所示，本节重点讨论在使用 logits 进行采样之前，用温度参数对其重新缩放。这里的重新缩放意味着调整分数的大小，使得采样步骤对分数差异的敏感度发生变化。

图 4.8 在本节中，我们将实现温度缩放的核心部分（步骤 3.2），即调整下一个 token 的分数。这使得我们能在后续步骤中控制模型选择下一个 token 的置信度。

代码清单 4.4 通过温度缩放重新缩放下一个 token 的分数

在实际应用中，温度值应为正数，因此如果温度为零或负数，我们会抛出错误。稍后在将温度缩放添加到文本生成函数时，我们还会增加更多温度缩放的安全措施。

对于其他所有值，logits 均除以温度。温度为 1.0 表示不变，因为任何数除以 1 都保持不变。温度低于 1.0 会使分布更尖锐，使模型在选择下一个 token 时更自信。温度高于 1.0 会使 logit 分布更平坦，这可以使采样（图 4.8 中的步骤 3.4）更多样化。换句话说，更高的温度降低了最高分 token 与低排名 token 之间的概率差距，增加了采样选中非最大 token 的机会。

为什么叫温度？

"温度"一词来源于物理学，在物理学中温度控制系统中随机性或运动的大小。在 LLM 中，我们使用同样的概念来控制模型选择下一个 token 时的置信度或创造性，你将在后续章节中看到这一点。

Softmax 函数的底层原理

Softmax 函数将原始分数（logits）向量转换为概率分布，其中每个值介于 0 和 1 之间，且所有值之和为 1。这种转换使数值更易于解释，也便于后续从中采样。

如果你熟悉数学符号，softmax 函数的公式为：

\[ \text{softmax}(z_i) = \frac{\exp(z_i)}{\sum_j \exp(z_j)} \] 其中，\(z\) 是一个实数输入向量：

\[ z = [z_1, z_2, \ldots, z_n] \] 这里：

  • \(n\) 是向量中元素的数量。
  • \(i\) 是当前元素的索引（\(1 \leq i \leq n\)）。
  • \(j\) 是用于对所有元素求和的索引（\(1 \leq j \leq n\)）。

由此得到每个元素 \(z_i\) 的归一化概率，满足：

\[ \sum_i \text{softmax}(z_i) = 1 \] 在代码中，softmax 函数可以用三行实现：

在实践中，我更喜欢使用 torch.softmax 函数，因为它有一些额外的数值稳定性改进，能够更可靠地处理极小和极大的值。

将 logits 转换为概率分数的目的是使结果更易解释，并且我们现在可以使用 torch.multinomial 函数从中采样。例如，如果从这个概率分布中抽取一个样本，在温度为 5.0 的设置下，我们有 0.03% 的概率得到 " Berlin"（而在温度为 0.5 时，有 33.98% 的概率得到 " Berlin"）。

多项式采样

多项式采样是在给定词汇表概率分布（如 softmax 概率分数）的情况下，选择下一个 token 的过程。在多项式采样中，我们并非总是选择最可能的 token（称为贪婪解码），而是随机抽取一个 token，概率越高的 token 越有可能被选中。这种随机性对于生成多样化的响应至关重要，我们将在后续的自一致性采样中使用这一特性。

为了进一步说明这一点，我们可以将概率分数看作一组加权选择。例如，一个概率为 0.40 的 token 出现的概率是一个概率为 0.10 的 token 的四倍，但两者都是可能的结果。

假设模型分配了以下概率：

  • "Berlin": 0.70
  • "Munich": 0.20
  • "Hamburg": 0.10

贪婪解码总是返回 "Berlin"。而多项式采样则根据这些权重抽取一个 token。在大量抽取中，"Berlin" 出现频率最高（70% 的时间），"Munich" 有时出现（20% 的时间），"Hamburg" 仅偶尔出现（10% 的时间）。

这种可变性使我们能够在后续小节中为自一致性生成多个候选答案。

4.5 用 top-p 采样平衡多样性与连贯性

Balancing diversity and coherence with top-p sampling

你已经看到温度缩放和采样（通过 torch.multinomial）如何增加 LLM 响应的多样性，无论这种多样性是好是坏。具体来说，你看到这种方法可能最终采样到与用户查询无关的词元。

现在，我们将通过添加一个 top-p 滤波器（图 4.12）来改进采样过程，使得极低置信度的词元不会被意外采样到。本节描述的 top-p 采样过程也称为核采样（nucleus sampling）。在本节中，我们实现 top-p 过滤，它选择一部分最高概率的词元进行采样。

图 4.12 top-p 过滤过程概览。 该滤波器通过对词元排序、应用累积截断、选择 top-p 子集并重新归一化结果，仅保留最高概率的词元。

图 4.12 总结了构成 top-p 滤波器的四个步骤：对词元概率进行排序、计算其累积和、选择满足 top-p 截断条件的子集，以及重新归一化剩余概率，使其再次形成一个有效的概率分布。重新归一化步骤是必要的，因为一旦我们移除所有低概率词元，剩余的概率之和就不再为 1。为了正确采样，我们需要重新缩放剩余值，使其代表一个适当的概率分布。

现在我们将详细讲解图 4.12 中的步骤 4.1 到 4.4。

Top-k 过滤

Top-k 过滤是在采样过程中限制候选下一个词元集的另一种方法。与保留所有累积概率低于阈值的词元不同（如 top-p），top-k 仅根据模型 logits 保留 k 个最可能的词元。在按概率对词汇表排序后，前 k 个条目之后的所有内容均被移除。剩余的 k 个词元随后被重新归一化并从中采样。

简而言之，top-k 保留固定数量的最可能词元，而 top-p 根据累积质量保留可变数量的词元。

Top-k 实现起来更简单，我在《Build a Large Language Model (From Scratch)》一书中介绍过它。Top-p 采样最近变得更流行了。

4.6 用自一致性提高响应准确性

Improving response accuracy with self-consistency

现在我们已编写了温度缩放和 top-p 过滤的代码，可以开始实现本章中的第二个推理时间缩放技术了：自一致性采样（self-consistency sampling）。

自一致性采样的想法来源于 Google Research 的论文《Self-Consistency Improves Chain-of-Thought Reasoning in Language Models》(https://arxiv.org/abs/2203.11171)。尽管名字很花哨，自一致性采样本质上是一种多数投票形式：我们使用温度缩放和 top-p 过滤生成多个答案，然后选择出现频率最高的一个，如图 4.17 所示。

图 4.17 所示的自一致性采样技术算是一种推理时间缩放技术，因为我们没有更新模型本身，而是花费更多的计算资源来提高响应准确性。

练习 4.4：自一致性采样中的早停

为了提高计算效率，实现自一致性的早停版本，在超过一半的答案一致时就结束采样。

选择温度和 top-p 设置

我们已经讨论过温度，但实际问题是：对于自一致性采样，我们应该引入多少随机性？我们的目标不是让模型尽可能随机，而是生成足够多样化的答案，使得多数投票能够起作用，同时仍然让大多数样本保持合理。在实践中，温度值在 0.5 到 0.9 左右，top-p 值在 0.7 到 0.9 左右，是合理的起点。

作为经验法则，如果所有长答案看起来几乎相同，那么最好温和地增加温度或 top-p 值以鼓励更多多样性。如果长答案开始看起来异常或毫无意义，那么设置可能过于激进，应该降低，通常首先降低温度。这里，"长"答案指在提取最终盒式结果之前的完整答案。你可以检查 self_consistency_vote 函数返回的结果字典中的长答案，或者使用 show_long_answer=True 设置运行该函数。

你可能还记得，描述这种技术的论文标题是《Self-Consistency Improves Chain-of-Thought Reasoning in Language Models》。"思维链推理"在这里如何发挥作用？这里的思维链推理简单地指我们本章前面介绍的思维链提示，即我们通过 "\n\nExplain step by step." 修改提示，使 LLM 生成更长的响应。

第 4 行展示了为基础模型添加温度缩放和 top-p 采样后的结果。（表 4.1 中所有涉及温度缩放和 top-p 采样的实验都将两者设置为 0.9。）相对于第 1 行的基础模型，准确率仅适度提高，从 15.2% 提升到 17.8%。这是意料之中的，因为温度缩放和 top-p 采样仅仅帮助我们控制采样多样性，它们本身并不是推理时间缩放技术。我们还可以看到运行时间从 10.1 分钟增加到了 30.7 分钟。这不是由于采样代码的开销，而是因为模型在某些情况下现在生成了更长的响应。

在实践中，如果你有多个 GPU，自一致性采样中的不同样本可以并行计算，而不是顺序计算。这仍然使用相同数量的计算资源，但可以分布在多个 GPU 上以更快地生成结果。

最后，在第 12 行，我们可以看到推理变体也从自一致性采样中受益，准确率从第 2 行的 48.2% 提高到 55.2%。同样，这也伴随着运行时间的增加。

关键是，表 4.1 中的结果凸显了推理时间缩放中的权衡：更高的准确率需要更多的计算量。

本章中自一致性采样方法的一个主要缺点是，它依赖于我们可以提取出来进行多数投票的最终盒式答案。这种方法对于没有数值或简短最终答案的问题来说应用起来比较棘手。

在下一章中，如图 4.19 所示，我们将实现一种不同且更通用的推理时间缩放方法，称为自我改进（self-refinement），其中模型迭代地改进自己的答案。

图 4.19 本章重点关注的推理时间技术总结。 在此，文本生成函数通过基于投票的方法进行了扩展，以提高答案准确性。下一章将介绍自我改进，模型在其中迭代改进其响应。

总结

  • 推理能力和答案准确性可以通过在推理时增加计算量来改进，而无需重新训练模型（推理时间缩放）。
  • 一个灵活的文本生成包装器（generate_text_stream_concat_flex）允许插入不同的采样策略，而无需更改周围的代码。
  • 下一个词元通过 softmax 从 logits 产生。
  • 温度缩放改变 logits，以控制生成文本的多样性。
  • Top-p（核）采样过滤掉低概率词元，以减少生成无意义答案的机会。
  • 思维链提示（如"请逐步解释。"）通常通过鼓励模型写出其中间推理过程来产生更准确的答案，尽管它增加了生成的词元数量，从而增加了运行时间成本。
  • 自一致性采样生成多个答案，从每个答案中提取最终的盒式结果，并通过多数投票选择最频繁的答案以提高答案准确性。
  • 在 MATH-500 数据集上的实验表明，将思维链提示与自一致性结合，可以相对于无采样基线大幅提高准确率，但代价是运行时间大大增加。
  • 推理时间缩放的核心权衡是：更高的准确率换取更多的计算量。
