第6章 使用强化学习训练推理模型

Training reasoning models with reinforcement learning

本章涵盖

  • 人类反馈强化学习（RLHF）与可验证奖励强化学习（RLVR）之间的区别
  • 将推理大模型的训练视为一个以任务正确性奖励为目标的强化学习问题
  • 每个提示词采样多个响应以计算群组相对学习信号
  • 使用基于群组的策略优化算法更新大模型权重以提升推理能力

This chapter covers

  • The difference between reinforcement learning with human feedback and reinforcement learning with verifiable rewards

  • Training reasoning LLMs as a reinforcement learning problem with task-correctness rewards

  • Sampling multiple responses per prompt to compute group-relative learning signals

  • Updating the LLM weights using group-based policy optimization for improved reasoning

Reasoning performance and answer accuracy can be improved both by increasing the inference compute budget and by using specific model-training methods. This chapter, as shown in figure 6.1, focuses on reinforcement learning (RL), the most commonly used training method for reasoning models.

We’ll first go through a general introduction to RL in the context of LLMs. Then we’ll discuss the two most common RL approaches used for LLMs.

6.1 LLM强化学习简介

Introduction to RL for LLMs

推理时扩展（inference-time scaling）和训练时扩展（training-time scaling）是提升LLM推理性能的两种不同方法，如图6.2所示。推理时扩展通过在每次生成答案时投入更多计算来提升准确率，而训练时扩展则通过在训练期间投入更多计算来提升准确率。本章聚焦于训练时扩展。

虽然图6.2将推理时扩展和训练时扩展作为独立概念呈现，但在实践中它们可以结合使用。例如，通过RL（本章的核心焦点）提升模型的推理能力后，可以应用第4章和第5章介绍的推理时扩展技术来进一步提高性能。

RL关注模型如何从动作序列及其结果中学习，经典例子包括训练智能体下棋、下围棋或玩电子游戏。虽然LLM的RL建立在这些研究基础之上，但在重要方面有所不同，且通常与熟悉的LLM训练技术相似。由于本书聚焦于语言模型，我们不会泛泛地介绍RL，而是聚焦于RL如何在LLM训练中应用。

那么，RL对于LLM在实践中意味着什么？在高层面上，RL通常作为预训练语言模型之上的后训练阶段应用，有时在指令微调之后。这一设置如图6.3所示。

LLM有两个常见的RL阶段：推理训练和偏好调优。如图6.3所示，RL通常在指令微调之后应用，而偏好调优通常在推理训练之后进行。

图6.2 推理时扩展与训练时扩展的概念对比。增加推理时的计算量通过每次生成答案投入更多资源来提升准确率，而增加训练时的计算量则通过预先投入更多资源来提升准确率。

图6.3 LLM的常见训练阶段。推理训练和偏好调优阶段的顺序可以变化，有些流程将推理和偏好调优交织进行而非严格排序。

正如DeepSeek团队在其DeepSeek-R1工作中所展示的，聚焦推理的RL也可以直接应用于预训练基础模型，跳过指令微调和偏好调优。由此得到的模型在推理准确率上通常弱于经过完整训练流程的模型，但它仍然展现出清晰、稳健的推理行为。更重要的是，直接将推理训练应用于基础模型避免了混合多个训练阶段的效果，使得任何观察到的改进更容易归因于推理训练本身。

在深入探讨RL如何在LLM中实现的细节之前，让我们先在概念层面简要比较RL和预训练。 在预训练期间，LLM被训练来预测大量文本中的下一个token，模型的许多核心能力和涌现行为（如回答基于知识的问题和遵循简单指令）都在这个阶段发展。

注： 预训练是我前一本书《从头构建大语言模型》（Build a Large Language Model (From Scratch)）的主要焦点，但熟悉该材料并非理解本章或本书其余部分的必要条件。

在预训练模型之上应用RL具有吸引力，因为它让我们优化整个输出（如答案正确性或偏好），而不是单个token和下一个token预测。在这个意义上，预训练主要构建知识，而RL塑造模型如何使用这些知识，包括其推理行为。

如图6.4所示，接下来的两个小节概述了RL在LLM训练中的使用方式，并为我们将在本章其余部分使用的方法提供了背景。

图6.4 本章路线图。在本节简要介绍LLM的RL之后，我们将讨论两个RL阶段RLHF和RLVR之间的区别。在章的其余部分，我们将聚焦于使用GRPO算法实现RLVR。

6.1.1 原始的基于人类反馈的RL流程（RLHF）

The original RL pipeline with human feedback (RLHF)

2022年，InstructGPT论文《Training language models to follow instructions with human feedback》（https://arxiv.org/abs/2203.02155）引入了基于人类反馈的强化学习（RLHF），这是一种利用人类偏好标签来调整模型行为的训练方法。事实上，RLHF是将GPT-3转化为ChatGPT中使用的原始模型的关键要素，这可以说在2022年使LLM广泛流行。

在高层面上，RLHF是实现偏好调优阶段最流行的方法。在RLHF之前，LLM主要通过预训练和在某些情况下的监督微调来训练，两者都基于下一个token预测目标。RLHF超越了这种token级别的优化，转而优化模型的整个输出（在这种情况下，RLHF优化的是人类如何排序和评估LLM输出）。

为了更具体地说明，考虑以下提示："我正在寻找一台用于编程和日常使用的笔记本电脑，应该考虑哪些因素？"

模型可能生成两个候选回答：

  • 回答A："你应该考虑CPU、内存、存储、GPU、屏幕分辨率、电池续航、键盘质量、接口选择、散热设计和价格。"
  • 回答B："对于编程和日常使用，聚焦于快速的CPU、至少16GB的内存和至少256GB的SSD存储。舒适的键盘和良好的电池续航也很重要。如果你计划本地训练小型LLM，GPU才可能有关。"

两个回答都提到了相关要点，但人类数据标注员可能更偏好回答B，因为它更具体，且针对提示中所述的使用场景。在RLHF中，这种成对偏好会在许多提示上收集，并用于训练模型偏好人类评分更高的回答。

如图6.5所示，RLHF有两个主要步骤：（1）训练一个奖励模型（它本身就是一个LLM），（2）使用该奖励模型为目标LLM的输出评分并进行微调。

步骤1：训练奖励模型

  • 从输入提示中采样多个回答（例如，使用上一章的温度和top-p采样）

  • 人类按偏好对不同的回答进行排序

  • 使用排序后的回答训练一个输出数值分数的奖励模型

步骤2：使用奖励模型计算奖励并更新LLM

  • 采样一个回答
  • 用训练好的奖励模型对回答评分
  • 在RL目标中使用奖励分数计算训练信号，用于更新要训练的模型

图6.5 基于人类反馈的强化学习（RLHF）的两阶段概览。首先，奖励模型在人类排序的回答上进行训练，为每个回答分配一个偏好分数。其次，LLM通过RL目标使用这些奖励分数进行更新，以鼓励偏好的回答并抑制不太理想的回答。

RLHF的第一步是训练一个奖励模型，如图6.5顶部子面板所示。这里，我们让LLM为每个提示生成多个回答（例如，使用第4章介绍的温度缩放和top-p过滤方法），并请人类标注员根据人类偏好对答案从最好到最差进行排序。

这些人类偏好通过一个统计偏好模型转化为奖励模型的训练目标，该模型将成对比较映射为相对质量分数。奖励模型通常是一个单独的模型，从预训练LLM初始化，训练为每个回答输出一个单一数字（标量）的奖励分数，反映其感知质量。其思想是奖励模型可以自动评分新的模型输出，从而无需在每个训练步骤都进行人工标注。

RLHF的第二步是在奖励模型对其答案分配的奖励分数上训练LLM（例如，一个差答案可能得–2，一个好答案可能得+2）。

我们在这里讨论RLHF，是因为它可以被视为聚焦推理的RL方法（如基于可验证奖励的强化学习，RLVR）的前身。虽然RLHF和RLVR的训练信号来源不同，但其流程的底层结构（生成回答、评分、通过RL更新模型）是密切相关的。

6.1.2 从人类反馈到可验证奖励

From human feedback to verifiable rewards

RLHF可能相当复杂，因为它需要训练一个额外的奖励模型，这通常是一个大型LLM，训练成本也很高。基于可验证奖励的强化学习（RLVR）通过用可验证奖励替换LLM奖励模型来简化这一设置，可验证奖励是确定性计算的，无需人工标注。例如，第3章介绍的数学验证器就是数学问题的可验证奖励生成器。给定一个数学问题（和一个正确答案），数学验证器自动检查生成答案的最终结果是否与真实答案匹配，并分配相应的奖励：正确回答得1分，错误回答得0分。

在RLVR中，图6.5所示的两步RLHF流程压缩为类似RLHF中步骤2的单一训练循环：模型生成回答，验证器分配奖励，这些奖励直接用于更新模型。这个简化的RLVR训练过程如图6.6所示。

图6.6 RLVR概览。LLM生成一个回答，由确定性验证器（如第3章的数学验证器）评估，该验证器分配一个正确性标签，用作RL目标中的奖励信号来更新模型。

RLVR的流行很大程度上可以归因于2025年DeepSeek-R1的成功（https://arxiv.org/abs/2501.12948），它证明了无需依赖人类偏好数据或学习的奖励模型即可实现强大的推理性能。DeepSeek-R1通过使用自动可验证奖励来训练推理行为，包括数学问题的正确性检查（类似于第3章中的验证器）和代码相关任务的编译与执行。

代码执行超出了本书的范围，因为需要在安全的执行环境中训练LLM。这意味着要在隔离的沙箱中编译和运行模型生成的代码，使其无法以不安全的方式访问主机系统、私有文件或外部服务，这会使设置远比解决数学问题复杂。无论如何，验证数学任务（检查答案是否正确作为二元标签）和代码编译（检查代码是否能编译，同样作为二元标签）背后的思想是相似的，RLVR训练算法也是相同的。

总结来说，RLVR相比RLHF有几个实际优势。首先，它消除了训练和维护单独的奖励模型（其规模和成本通常与基础LLM相当）的需要。

其次，RLVR需要访问可靠的验证信号，这将其限制在特定领域，如数学和代码。但可验证奖励是确定性和可复现的，意味着对于相同的输出，每次都会产生相同的结果，这避免了人类偏好标注中的噪声和不一致性。

最后，RLVR可以自然地扩展到大型训练集，因为给定参考解，奖励可以自动计算任意数量的模型生成答案，无需额外的人工标注工作。

6.2 使用GRPO实现RLVR

RLVR using GRPO

现在我们已经了解了全局，看到了RL如何适配LLM的整体开发生命周期，我们将转向实现。具体来说，我们将实现RLVR来训练一个推理模型，如图6.7中的章节路线图所示。这种方法类似于DeepSeek-R1-Zero，但我们将在更小的规模上应用，使用更小的模型和更少的数据，因为一个完整的等效训练运行在GPU计算上需要几十万美元。

RLVR定义了整体训练设置，即使用自动可验证奖励。此外，我们还需要一个具体的策略优化算法，可以在RLVR框架内用于更新模型权重并训练模型。

术语"策略"（policy）是RL领域的行话，在此上下文中指我们想要训练的LLM。具体来说，我们将使用组相对策略优化（Group Relative Policy Optimizatio）（GRPO）算法进行策略优化。简言之，RLVR决定了可用的学习信号，GRPO决定了如何使用该信号更新模型权重。

图6.7 我们已经看到了LLM的两种主要RL方法：RLHF和RLVR。本章的剩余部分聚焦于使用GRPO算法实现RLVR，从加载数据集到实现完整的训练循环。

策略梯度算法

LLM中广泛使用的策略梯度算法是近端策略优化（PPO），它在RLHF中得到了普及。原则上，同样的算法也可以应用于RLVR设置。

在训练DeepSeek-R1推理模型时，DeepSeek团队选择了更简单的替代方案GRPO，该算法最初在其DeepSeekMath论文（https://arxiv.org/abs/2402.03300）中提出。GRPO比PPO更节省资源，因为它不需要单独的价值模型来估计价值函数。相反，GRPO从一组采样回答中的相对比较中推导出其学习信号，这大大降低了计算开销。如果你感兴趣，可以在我的文章《LLM推理的强化学习现状》（https://magazine.sebastianraschka.com/p/the-state-of-llm-reasoning-model-training）中找到PPO和GRPO更详细的并列比较。

在本章中，我们将聚焦于使用GRPO实现RLVR，正如DeepSeek-R1和其他流行的推理模型所使用的。在下一章中，我们将在此基础之上构建，并介绍GRPO的几个实用扩展，以进一步提高训练稳定性和推理性能。

6.2.1 通过厨师类比理解GRPO高层直觉

High-level GRPO intuition via a chef analogy

GRPO算法用于RLVR的技术细节起初可能有些令人不知所措，因为它有很多活动部件和大量的RL领域专用术语。因此，在开始技术概述和实现之前，先看看图6.8，它通过厨师准备餐点的类比来介绍GRPO的技术术语和方法。

图6.8 使用厨师类比展示GRPO算法用于RLVR的概览。生成多个卷展（rollouts）并进行评分，计算相对优势（advantages），然后使用带有KL正则化损失项的策略梯度目标来更新模型参数。

走一遍图6.8中的流程图，想象我们正在运营一个小型的食品配送服务：

  1. 每天，我们收到一个客户请求（即提示），要求我们准备某道菜（例如，千层面）。
  2. 针对该请求，我们烹饪拿手的千层面，但在此过程中尝试几种不同的配方变体（即卷展，rollouts）。
  3. 准备好配方后，我们制作多道菜（即完成，completions）。注意，在LLM设置中，卷展指为某个提示生成的全部过程，而完成指最终输出的文本。实践中，这两个术语通常互换使用。
  4. 顾客只在品尝完整道菜后才给我们反馈（即奖励，reward），而不是在烹饪过程中。这意味着我们评判的是最终结果整体，而非评判各个烹饪步骤。
  5. 我们根据第4阶段的顾客反馈比较各道菜的相对表现。这帮助我们确定对于这一特定请求，哪些配方变体获得了更高奖励，哪些获得了更低奖励。
  6. 对于每道完成的菜，我们还记录它对我们当前烹饪风格的典型程度，即它在多大程度上遵循了我们通常的技法和食材选择（即对数概率，logprobs）。
  7. 利用第5阶段的相对反馈和第6阶段每道菜对我们当前烹饪风格的特征程度，我们确定如何调整烹饪风格（即策略梯度损失，policy gradient loss）。这里，我们要强化导致更好菜肴的选择，削弱导致更差菜肴的选择。
  8. 同时，我们查阅原始食谱。
  9. 然后，我们应用一个风格保留惩罚（style-preservation penalty），鼓励尝试新的配方变体，但防止对烹饪风格进行过于剧烈的改变，以免吓跑现有顾客。
  10. 基于偏好的调整和烹饪风格保留惩罚被合并为一个单一的总体度量，即总体损失（total loss），决定烹饪风格应如何改变。目标是平衡顾客满意度和一致性。
  11. 最后，我们更新烹饪风格（即基于梯度的模型权重更新），使未来的菜肴更可能满足顾客偏好，同时保持与原始食谱接近。

即使在这个相对基础的类比中，GRPO仍然有很多组件和活动部件。

6.2.2 GRPO高层流程

The high-level GRPO procedure

沿用上节的厨师类比，图6.9中的流程图提供了GRPO算法用于RLVR的技术概览，其中包含我们在逐步实现GRPO时将计算的具体值。

图6.9 RLVR的逐步GRPO更新。（1）采样一个提示并生成多个卷展。（2）每个卷展使用可验证奖励进行评分。（3）从这些奖励计算组相对优势。（4）计算每个卷展在当前模型下的对数概率。（5）将优势和对数概率结合形成策略梯度损失。（6）添加针对参考模型的KL正则化项，得到的总体损失用于更新模型参数。

图6.9中的GRPO概览包含许多技术组件。我们将从实现GRPO的简化版本开始，省去图右侧显示的KL损失项。在第7章中，我们会添加这个缺失的KL损失项以保持完整性。KL损失是原始GRPO公式的一部分，但它并非严格必要。许多LLM开发者实践中会省略它，因为这样简化了实现，有时还能提高建模性能。

注： 熟悉GRPO或其他策略梯度方法的读者可能会好奇裁剪策略比率（clipped policy ratios）的使用；我们将在下一章介绍。

如果图6.9中的概览看起来很复杂，不用担心。我们将一步步构建算法。现在，最好将图6.9视为一个高层路线图，帮助我们在处理各个部分时保持方向。

6.7 通过优势从卷展准备学习信号

你可能仍然想知道将奖励转换为优势的意义何在。在实际层面，优势值在策略更新期间直接缩放梯度。如果优势为正，梯度会增加产生该卷展的动作的似然。如果为负，梯度会降低其似然。优势接近零的卷展贡献很小。

如图 6.16 所示，这些 logprob 与优势一起构成了 GRPO 策略梯度损失的核心要素，我们将在后续实现它。

在上一章（代码清单 5.8）中，我们实现了一个 avg_logprob_answer 函数，该函数计算模型回答 token 的逐 token logprob。这些值是通过评估模型在其当前参数下分配给每个生成 token 的似然得到的。

当对整个回答取平均时，这些值通常被称为 token 级 logprob，并常用于对 LLM 输出进行评分。在这种上下文中，取平均是首选方法，因为它提供了长度归一化，使得不同长度的回答之间具有可比性。

token 级对数概率的数学定义

从数学上讲，我们在上一章中计算的 token 级 logprob 可以写成： \[ \log P(y_1, \ldots, y_T \mid x; W) = \frac{1}{T} \sum_{t=1}^{T} \log P(y_t \mid y_{<t}, x; W) \tag{6.1} \] 其中：

  • \(y_1, y_2, \ldots, y_T\) 表示生成的回答中的 token，长度为 \(T\)
  • \(y_{<t}\) 表示之前生成的所有 token
  • \(x\) 是输入提示
  • \(W\) 表示模型的权重参数

这个表达式在数学上与前一章使用的完全相同；我们只是将 \(x\) 换成了 \(y\)，以便将生成的输出 token 与输入提示区分开。

在 GRPO 中，我们不使用平均后的 token 级 logprob。相反，我们使用序列级 logprob。这是因为 GRPO 为每个 rollout 分配单一的奖励和优势，该奖励和优势适用于整个生成的回答。直观地说，logprob 应该反映模型生成整个序列的可能性，而不是每个 token 的平均值。

我们通过将所有生成 token 的 logprob 相加来计算序列级 logprob（该总和对应于在当前模型参数下生成完整回答的对数似然）。相比之下，对 token 级 logprob 取平均会按序列长度进行归一化。虽然这种归一化对于评分和比较不同长度的回答很有用，但它会在策略优化中无意中重新缩放学习信号，导致长短不一的回答对更新的贡献不均匀。这种基于长度的重新缩放不是原始 GRPO 公式的一部分，GRPO 使用整个 rollout 的序列级 logprob。我们将在下一章改进算法时重新审视 token 级 logprob。

这些序列级 logprob 与序列长度 \(T\) 呈线性关系，这意味着较长的回答通常获得更负的 logprob 值。因此，对于两个同样好的答案，优化过程会隐式地偏向较短的答案，因为它的似然代价更低。因此，求和后的 logprob 会鼓励模型更早停止，除非生成更长的回答能够获得更高的奖励。

PyTorch 计算图、梯度和反向传播

当模型产生输出时，PyTorch 会记录从模型参数到该输出的每个数学操作。这个记录称为计算图。当我们随后运行反向传播时，PyTorch 利用这个图来执行反向传播算法；也就是说，它计算梯度，描述模型参数的变化会如何影响最终结果。如果一个操作是该图的一部分，PyTorch 就可以在训练过程中通过它计算梯度。

在策略梯度方法中，我们希望最大化优势加权 logprob，因为高优势 rollout 的高对数概率会改进策略。将这个目标乘以 \(-1\)，我们将最大化问题转化为等价的极小化问题。极小化负目标产生的参数更新与最大化原始目标完全相同，同时与 PyTorch 的优化器实现兼容。

最大化与极小化

为了用具体例子说明符号翻转，假设我们要最大化的目标是简单的标量值 \(f(x) = 3\)。

在最大化视角下，较大的值更好，所以 3 优于 2。PyTorch 优化器执行极小化，因此它们会试图减小这个值，这与我们的目标相反。

现在，假设我们翻转符号并将损失定义为 \(L(x) = -f(x) = -3\)。极小化 \(L(x)\) 现在就等价于最大化 \(f(x)\)。例如，如果 \(L(x)\) 从 -2 减小到 -3，那么 \(f(x)\) 就从 2 增加到 3。

策略梯度损失的数学定义

如果你觉得通过数学符号更容易理解计算，GRPO 中使用的策略梯度损失可以写成： \[ \mathcal{L}_{\text{PG}} = -\frac{1}{N} \sum_{i=1}^{N} A_i \cdot \sum_{t=1}^{T_i} \log P\left(y_t^{(i)} \mid y_{<t}^{(i)}, x^{(i)}; W\right) \tag{6.2} \] 其中：

  • \(N\) 表示 rollout 的数量
  • \(y_1^{(i)}, \ldots, y_{T_i}^{(i)}\) 是第 \(i\) 个生成回答（长度为 \(T_i\)）的 token
  • \(y_{<t}^{(i)}\) 表示该回答中所有之前生成的 token
  • \(x^{(i)}\) 是相应的输入提示
  • \(A_i\) 是整个 rollout 的优势

内部求和计算一个 rollout 的序列级对数概率，而外部平均计算所有 rollouts 的优势加权对数概率。

总结

  • 强化学习（RL）可用于在人类偏好标签和可验证奖励上训练 LLM。
  • RL 通常作为在预训练基座模型之上的后训练来应用，它可以被插入到 LLM 流水线的不同阶段，包括推理训练和偏好微调。
  • 基于人类反馈的强化学习（RLHF）通过两阶段设置优化人类偏好：从排序的回答中训练奖励模型，然后使用奖励分数来更新 LLM。
  • 基于可验证奖励的强化学习（RLVR）通过用确定性的、自动计算的验证器（例如，数学答案检查）替换学习的奖励模型来简化 RLHF。
  • GRPO 是一种策略优化算法，它将验证器奖励转化为参数更新。由于 GRPO 直接使用序列级奖励优化模型，无需单独的价值模型，因此特别方便。
  • GRPO 是用于 LLM 的其他 RL 算法的一种更节省资源的替代方案，因为它避免了训练单独的价值模型，而是从一组采样的 rollouts 内的比较中推导出学习信号。
  • "Rollout"指的是对提示的完整模型回答（补全）；奖励、优势和对数概率在后续步骤中从 rollout 计算得出。
  • 奖励由验证器计算，只有当最终答案正确且以要求的格式（如 "\boxed{}"）可提取时，才给予奖励。
  • 原始奖励通过相对于组均值和标准差归一化每个 rollout 奖励，转换为优势。
  • GRPO 还依赖于序列级对数概率，通过对生成的回答 token 上的 token 对数概率求和来计算。
  • 序列对数概率与优势一起，构成了 GRPO 中核心的策略梯度目标。
  • 完整的 GRPO 损失计算被组合成一个单一函数，该函数执行 rollout 采样、奖励计算、优势计算、对数概率计算和策略梯度损失计算。
  • 周围的训练循环是一个标准的深度学习循环，关键区别在于损失来自 GRPO，而不是传统的分类损失。
  • 训练是资源密集型的，因为每一步都需要生成多个（可能很长的）rollouts，但即使是短时间的 GRPO 运行，也能将 MATH-500 准确率从 15% 提升到 47%。
