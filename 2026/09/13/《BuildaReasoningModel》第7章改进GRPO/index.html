    第 7 章 改进 GRPO 用于强化学习

    Improving GRPO for reinforcement learning

    本章涵盖

    • 解读训练曲线和评估指标
    • 防止模型利用奖励信号
    • 用额外的回答格式奖励扩展任务正确性奖励

    This chapter covers

    • Interpreting training curves and evaluation metrics

    • Preventing the model from exploiting the reward signal

    • Extending task-correctness rewards with additional response-formatting rewards

    之前，我们从端到端实现了基于可验证奖励的强化学习（RLVR）的 GRPO 算法。现在，如图 7.1 所示，我们将从那个基线出发，重点讨论当我们运行更长时间训练时会发生什么。

    特别是，我们将讨论哪些指标值得追踪（不仅仅是奖励和准确率），如何及早发现失败模式，以及为什么即使代码是"正确的"，训练也可能变得不稳定。事实证明，基本的 GRPO 可能导致训练不稳定，因此本章还介绍了推理模型训练中使用的实用 GRPO 扩展和修复。

    本章对强化学习进行了更详细的处理，分析了训练结果并提出了改进建议。

    7.3.2 熵跟踪

    Entropy tracking

    在我们跟踪和分析上一节介绍的优势统计量之前，先介绍另一个指标——熵。

    熵衡量模型在生成下一个 token 时的不确定性。高熵意味着概率分布在许多可能的 token 上，这鼓励探索。低熵意味着大部分概率集中在一个 token 上，这使得模型越来越确定性。低熵也可能表示训练崩溃，即模型停止探索并持续产生相同的输出。

    在计算熵之前，让我们简要回顾一下我们在第 5 章中如何计算对数概率值（logprobs），如图 7.7 所示。

    图 7.7 LLM 生成答案中单个 token（"this"）的对数概率（logprob）计算。LLM 返回 token 的 logits，然后通过 torch.softmax() 转换为 softmax 概率值，或通过 torch.log_softmax() 转换为 logprob 值。

    在图 7.7 中，我们没有使用通过提示基础模型生成的实际 logits，而是使用示例 logits，假设词汇表大小为 7（否则，使用原始的 151,000 个 token 词汇表，将无法在图中可视化这个概念）：

    简而言之，torch.log_softmax() 计算所有的 logprob，torch.argmax() 返回最大 logprob 的索引（token ID，此处为 5），而 logprobs[selected_token] 返回该 token ID 的 logprob 值（–0.7109）。

    熵与 logprob 密切相关。我们通过将每个概率乘以其 logprob，然后将这些乘积求和来计算熵，如图 7.8 所示。原则上，我们也可以在训练期间跟踪比熵更简单的量，如概率之和或 logprob 之和，但熵是度量概率分布不确定性的一个广泛使用且易于理解的指标。

    图 7.8 显示熵为 1.37。作为粗略的经验法则：

    • 非常低的熵（≈ 0–0.5）意味着一个 token 主导了分布。模型高度自信，行为几乎确定性。
    • 中等熵（≈ 1–2）意味着概率分布在一个相当小的 token 集合上，这在稳定训练期间是典型的情况。
    • 高熵（接近 [log × 词汇表大小]；此处为 log(7) = 1.9459）意味着概率分布在许多 token 上。在这种情况下，模型高度不确定，行为几乎随机。

    清单 7.5 计算序列 logprob 和平均熵

    为了在训练期间计算和跟踪熵，我们可以在 compute_grpo_loss 中使用这个 sequence_logprob_and_entropy 函数来代替 sequence_logprob 函数。

    请注意，图 7.8 说明了展开中单个 token（step_entropy）的熵计算，而 sequence_logprob_and_entropy 返回所有答案 token 的平均熵，即 entropy_all_steps = torch.mean(step_entropy)。对于答案 "this is the LLM response"，步骤熵指的是单个 token 位置（例如，"this" 处）的熵，而平均熵是 "this is the LLM response" 中所有答案 token 的均值。

    有了这个修改后的 sequence_logprob_and_entropy 函数，我们现在可以在训练期间使用熵作为模型生成行为的诊断工具。通过跟踪生成答案 token 的平均熵，我们可以监测模型是随机行为（高熵）、保持探索性（中等熵），还是变得过度自信和确定性（低熵）。

    特别是，我们期望熵随着模型变得更加自信而逐渐降低。突然崩溃到非常低的熵可能是不稳定训练的警告信号。

    图 7.9 可视化 GRPO 训练运行期间跟踪的优势统计量和熵（旁边是先前跟踪的平均奖励）

    让我们首先分析图 7.9 中显示的优势。正如 GRPO 风格归一化所预期的，平均优势在整个训练过程中保持为零。由于优势是相对于组均值计算的，它们总和为零。如前所述，这个指标主要起健全性检查的作用。如果优势平均值偏离零，则表明存在 bug 或归一化问题。

    优势的标准差更具信息量。在训练早期，我们看到相对较高的方差，这表明模型产生的展开质量差异很大。随着时间的推移，优势标准差逐渐降低并稳定，这意味着展开的质量变得更加相似。关键点是，只要优势标准差保持非零且相对稳定（即值变化不大），就仍然存在可用的学习信号，训练仍在进行。

    接下来，让我们看看熵。在训练早期，熵相对较低且相当平坦，这表明模型的行为在很大程度上是确定性的。提高采样温度会导致更多样化的展开，尽管它不会改变模型自身的底层熵。

    在训练后期，大约在步骤 200 之后，熵明显增加。这意味着下一个 token 的概率更加分散，模型的行为更加随机。非常低的熵也可能是崩溃的迹象，即模型反复产生相同或非常相似的输出。在这次运行中，熵以及不断增加的平均奖励和非消失的优势标准差表明这是一种相对健康的探索，而不是崩溃。这也与早期的 MATH-500 评估准确率一致，后者保持在 30%–40% 的范围内。这不算很好，但也没有接近零。

    这里的主要收获是，每个指标都讲述了故事略有不同的部分，将它们放在一起并结合上下文考虑时最为有用。

    7.5 用KL项控制模型变化幅度

    Controlling how much the model changes with a KL term

    在第 6 章中，为了保持内容易于理解，我们在 GRPO 算法中跳过了 KL 损失项的使用。为了完整实现 GRPO 算法，我们现在将加入 KL 损失项，如图 7.14 所示。

    注：如果你熟悉强化学习，你可能会注意到我们目前实现的内容本质上是带有组归一化优势的 REINFORCE 算法。（有关 REINFORCE 方法的信息，请参见 https://lilianweng.github.io/posts/2018-04-08-policy-gradient/。）

    KL 是 Kullback-Leibler 散度的缩写，它衡量当前策略（即正在训练的 LLM）与参考策略（通常是训练起始时的原始模型）之间的偏差程度。KL 项起到约束作用（技术上称为正则化器），它阻止过大的更新，使模型保持接近其原始行为，防止剧烈或不稳定的变化。

    这与我们之前介绍的裁剪策略比率密切相关。通过裁剪策略比率，我们限制了单个更新步的大小。KL 项是控制模型变化幅度的另一种机制。裁剪策略比率侧重于限制步与步之间的变化，而 KL 项通常用于控制更长训练轨迹上的变化。

    现在我们将加入一个 KL 损失项，以防止与参考模型的剧烈变化。

    7.5.1 实现KL损失项

    Implementing the KL loss term

    图 7.15 展示了作为 GRPO 算法一部分的 KL 损失项计算过程。KL 损失项的计算涉及比较对数概率和参考对数概率。它通过求这些对应对数概率差异的总和来计算。

    KL 损失项的值较小，表明当前模型和参考模型输出的对数概率相对接近，这意味着当前模型相比参考模型变化不大。这对于稳定性通常是理想的，因为它能防止行为发生大的突变。如果 KL 损失项长时间保持过小，也可能意味着学习受限。

    计算出的 KL 损失项随后被加入策略梯度损失中以计算总损失，因此即使权重更新能带来高奖励，如果它们导致与参考模型的偏差过大，也会在训练中受到惩罚。

    在裁剪策略比率的章节中，我们在每次迭代中替换了参考模型。而对于 KL 损失项，用于计算参考对数概率的参考模型是训练开始时的原始模型，它要么保持固定，要么相对较少地被替换（以 DeepSeek-R1 为例，每 400 步替换一次）。

    通过人工检查生成的响应，我们可以看到模型最终开始生成无意义的文本和随机 token，例如 "framework.raises Self profess(import"。这种行为有几个可能的原因。

    首先，KL 项是针对答案 token 上的对数概率总和计算的，即 kl_loss = kl_coeff * mean(new_logps - ref_logps)。这里，new_logps 是在当前可训练策略下计算的，而 ref_logps 是在参考策略（即训练开始时的原始模型）下计算的。这个参考策略与后期训练步骤中的旧 rollout 策略不同。旧策略是用于生成采样响应的最近快照，而参考策略则固定在初始模型上。

    KL 方向与 rollout 采样：

    KL 散度是有方向的。如果我们从旧 rollout 策略中采样响应，并想衡量当前策略与该旧策略的差异程度，对应的样本级对数概率差应为 old_logps - new_logps。

    然而，这里的 KL 项有不同的目的。它旨在惩罚当前策略偏离固定参考策略的情况，因此对应的对数概率差是 new_logps - ref_logps。

    微妙之处在于，响应是由旧 rollout 策略生成的，而非更新后的当前策略。因此，mean(new_logps - ref_logps) 是一个简化的采样代理，而非精确的 KL 估计。更严格的离策略版本会使用重要性采样校正，我们将在下一小节讨论。

    由于该项未经长度归一化，其大小会随着响应长度增长。这并不意味着较长的输出总是被偏好，因为额外的 token 既可能增加也可能减少损失，这取决于当前策略和参考策略之间每个 token 的对数概率差。然而，由于 rollout 是从旧策略中采样的，这种简单的采样代理并不是当前策略的精确 KL 估计，除非我们直接从当前策略采样或应用重要性采样校正。因此，目标函数变得对长度敏感，在某些情况下可能使训练偏向较长的输出，正如这里响应长度不断增长所暗示的那样，并且可能破坏训练稳定性。

    其次，一旦奖励在第 200 步左右降至零，KL 项就成为梯度信号的唯一来源。当所有奖励为零时，优势也为零，因此策略梯度损失不再贡献任何梯度。KL 项仍然活跃，开始主导更新。在精确的 KL-参考目标中，这会将模型拉回参考策略。然而，这里使用的简化 KL 代理——kl_loss = kl_coeff * mean(new_logps - ref_logps)——仅在从旧策略采样的 rollout 上进行评估，且 ref_logps 在优化过程中是常数。在这些固定的采样 token 上，最小化损失主要会压低当前模型对采样动作的概率，这会使下一 token 分布更加分散，提高熵。观察到的行为更像是这种采样代理的失败模式，可能导致越来越随机的输出以及评估准确率降至 0.0%。如果你愿意，可以绘制其他评估指标，如 policy_ratio、adv_avg、adv_std 和 entropy_avg，并确认熵变得非常大。

    虽然 KL 项是 GRPO 算法的标准组成部分（这也是我在此介绍它的原因），但最近的一些研究报告称，模型在没有它的情况下训练效果可能更好。例如 Dr. GRPO、Olmo 3 和 DeepSeek-V3.2，它们都观察到在减少或省略 KL 项时稳定性或性能有所提升（详见附录 A 的参考文献）。

    使用 KL 项提升训练稳定性：

    或者，除了移除 KL 项，还有几种方法可以提升训练稳定性。首先，我们可以将 kl_coeff 从 0.02 减小到更小的值（例如 0.001）以减弱 KL 惩罚，尽管在我的实验中这并不足够。

    由于我们看到响应长度持续增长直到达到上限，另一种选择是对序列对数概率进行长度归一化，即除以生成的 token 数，这样可以得到每个 token 的平均对数概率近似值。这可以减少通过增加响应长度来累积更大绝对对数概率差的动机。

    第三种选择是使用基于重要性采样的重新加权 KL 项，正如 DeepSeek-V3.2 所提出的那样。这很重要，因为 rollout 是由旧策略生成的，而 KL 项的目的是约束当前策略相对于参考策略的偏离。与其使用：

    7.6.3 更多GRPO修改、技巧与窍门

    More GRPO modifications, tips, and tricks

    在第 6 章中，我们实现了一个没有 KL 损失项、带有裁剪策略比率和格式奖励的 GRPO 版本作为入门介绍。然后我们在本章加入了这些概念，为理解原始 GRPO 算法奠定了坚实的基础，该算法是现代大多数推理训练框架的基础。图 7.21 概述了下一步，我们将讨论额外的修改、技巧与窍门。

    图 7.21 本章最后一节概述了最近出现的其他 GRPO 修改方法

    就 GRPO 的 RLVR 应用而言，我们了解到有许多可调参数。除了更改基本设置（如学习率、最大响应长度和提示格式）之外，还有几乎无穷无尽的设置和修改可以尝试。深入探索单个修改或一小部分修改，对于一个小型研究团队来说可能成为一个持续数月甚至数年的研究项目。

    算法预计会不断变化和发展。不过，理解其背后的基本原理和总体思想非常重要，这样你才能理解和欣赏这些改进。

    在 DeepSeek-R1 成功后的几个月里，许多研究人员提出了对原始 GRPO 算法的改进，这些改进提升了训练稳定性和最终性能。以下精选的改进建议来自 DAPO、Dr. GRPO、DeepSeek-V3.2 等（完整的参考文献和链接列表请参见附录 A）：

    1. 过滤零梯度样本（DAPO）：跳过所有采样响应获得相同奖励的提示，因为这些组不产生有用的优势信号。
    2. 使用主动采样（DAPO）：过采样或优先处理能产生正确和错误响应混合的提示，因为这些提示提供更强的学习信号。
    3. 从序列级损失切换为 token 级损失（DAPO）：在单个 token 而非整个响应上计算损失，这可以减少与长度相关的偏差。
    4. 省略 KL 损失项（DAPO 和 Dr. GRPO）：当 KL 惩罚损害稳定性或性能时移除它，尤其是在数学推理场景中。
    5. 使用更大的裁剪范围（DAPO）：放宽裁剪阈值，使策略在奖励信号可靠时可以做出更大的更新。
    6. 截断重要性采样比率（verl）：对非常大的重要性权重设置上限，以防止少数离策略样本主导更新。
    7. 移除优势的标准差归一化（Dr. GRPO）：相对于组均值归一化奖励，但避免除以奖励标准差。
    8. 按领域调整 KL 强度（DeepSeek-V3.2）：对不同数据类型使用不同的 KL 系数，包括对数学任务使用零 KL。
    9. 使用重要性采样重新加权 KL 项（DeepSeek-V3.2）：当 rollout 从旧策略而非当前策略采样时校正 KL 估计。
    10. 掩码不合适的离策略序列（DeepSeek-V3.2）：排除在当前策略下可能性过低的 rollout 序列。
    11. 保留 top-p 或 top-k 采样的采样掩码（DeepSeek-V3.2）：仅在实际采样期间可用的 token 集上计算概率。
    12. 保留原始 GRPO 优势归一化（DeepSeek-V3.2）：当标准基于组的优势归一化在经验上效果良好时保留它。
    13. 在聚合前分别归一化每个奖励组件（GDPO）：在将不同奖励类型合并为总奖励之前，分别对其进行归一化。
    14. 应用序列级重要性采样和裁剪（GSPO）：在完整序列级别而非仅在 token 级别校正和裁剪更新。
    15. 裁剪重要性采样权重而非 token 更新（CISPO）：直接限制重要性权重，使离策略校正保持稳定。

    这些修改的详细解释、代码示例和训练运行结果超出了本章的范围。如果你感兴趣，可以在本书的补充材料中找到，网址为 https://mng.bz/nZVv。

    总结

    • 使用 GRPO 训练推理模型在较长运行中可能变得不稳定，即使实现正确且奖励初始有所改善。
    • 解释 GRPO 训练需要联合跟踪多个指标（平均奖励、响应长度、评估准确率、优势统计量和熵）：
      • 基本指标（如损失）主要用作 GRPO 的合理性检查，不应孤立地过度解读。
      • 优势统计量提供有用的诊断信息：均值应设计上接近零，而标准差反映了学习信号的强度和稳定性。
      • 熵衡量模型在生成过程中的不确定性。极低的熵可能意味着崩溃，而极高的熵可能表明更新不稳定和模型响应的随机性。
    • 裁剪策略比率限制了策略在更新之间的变化幅度，可以显著提升较长运行中的训练稳定性。
    • 加入 KL 散度项约束了相对于参考模型的长期漂移，但当奖励崩溃时可能破坏训练稳定性。
    • 对于数学推理任务，最近的一些系统报告称完全省略 KL 项可以获得更好的稳定性和性能。
    • 辅助格式奖励可以改善响应结构，例如鼓励使用 thinking 和 response token。
    • 除了原始 GRPO 算法之外，许多最近的扩展修改了优势归一化、重要性采样、裁剪策略和 KL 处理方式，以提升稳定性和效率。
