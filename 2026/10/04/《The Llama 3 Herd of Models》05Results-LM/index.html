5 结果

Results

我们对 Llama 3 进行了一系列广泛的评估，考察了以下方面的性能：（1）预训练语言模型，（2）后训练语言模型，以及（3）Llama 3 的安全特性。以下各小节分别报告这些评估结果。

5.1 预训练语言模型

Pre-trained Language Model

本节报告我们的预训练 Llama 3（第 3 节）与其他同等规模模型的评估结果对比。在可能的情况下，我们会复现竞争模型的结果。对于非 Llama 模型，我们报告公开可查结果中的最佳得分，或（在可能的情况下）我们自己复现的结果。这些评估的具体细节，包括 few-shot 样本数、指标及其他相关超参数和设置，可在我们的 GitHub 仓库中查看。此外，我们还发布了评估过程中生成的数据，这些数据可在 Huggingface 上获取。我们在标准基准（第 5.1.1 节）上评估模型质量，考察对多项选择题设置变化的鲁棒性（第 5.1.2 节），以及对抗性评估（第 5.1.3 节）。我们还进行了污染分析，以估计训练数据污染对评估结果的影响程度（第 5.1.4 节）。

显著性估计（Significance estimates）. 基准得分是对模型真实性能的估计。由于基准集是从某个潜在分布中抽取的有限样本，这些估计存在方差。我们遵循 Madaan et al. (2024b) 的做法，通过 95% 置信区间（CI）报告方差，假设基准得分服从高斯分布。虽然这一假设并不完全正确（例如，基准得分是有界的），但初步的 bootstrap 实验表明，对于离散指标，CI 是一个良好的近似：CI(S) = 1.96 × √(S × (1 − S) / N)。其中 S 是观察到的基准得分（如准确率或 EM），N 是基准的样本量。对于非简单平均的基准得分，我们省略 CI。我们注意到，由于子采样并非唯一的变异来源，我们的 CI 值实际上是能力估计实际变异的下界。

5.1.2 模型鲁棒性

Model Robustness

除了基准性能外，鲁棒性是预训练语言模型质量的重要因素。我们研究了预训练语言模型对多项选择题（MCQ）设置中设计选择的鲁棒性。先前的研究报告称，模型性能可能对此类设置中看似任意的设计选择非常敏感，例如，模型得分甚至排名可能随上下文示例的顺序和标签（Lu et al., 2022; Zhao et al., 2021; Robinson and Wingate, 2023; Liang et al., 2022; Gupta et al., 2024）、提示的确切格式（Weber et al., 2023b; Mishra et al., 2022）或答案选项的格式和顺序（Alzahrani et al., 2024; Wang et al., 2024a; Zheng et al., 2023）而改变。受此启发，我们使用 MMLU 基准评估预训练模型在以下方面的鲁棒性：（1）few-shot 标签偏差，（2）标签变体，（3）答案顺序，以及（4）提示格式：

  • Few-shot 标签偏差（Few-shot label bias）. 遵循 Zheng et al. (2023) 和 Weber et al. (2023a) 的方法，我们研究了四个示例中标签分布的影响。具体地，我们考虑了以下设置：（1）所有 few-shot 示例具有相同标签（A A A A）；（2）所有示例具有不同标签（A B C D）；（3）仅有两种标签出现（A A B B 和 C C D D）。

  • 标签变体（Label variants）. 我们还研究了模型对不同选项标记集的响应。我们考虑了 Alzahrani et al. (2024) 提出的两组标记：一组是常见的语言无关标记（$ & # @），另一组是罕见标记（œ § з ü），它们没有任何隐含的相对顺序。我们还考虑了规范标签的两个版本（A. B. C. D. 和 A) B) C) D)) 以及一个数字列表（1. 2. 3. 4.）。

  • 答案顺序（Answer order）. 遵循 Wang et al. (2024a) 的方法，我们计算了结果在不同答案顺序下的稳定性。为此，我们根据一个固定的排列重新映射数据集中的所有答案。例如，对于排列 A B C D，标签为 A 和 B 的所有答案选项保持原标签，标签为 C 的所有答案选项变为标签 D，反之亦然。

  • 提示格式（Prompt format）. 我们评估了五种不同信息量任务提示下的性能方差：一种提示仅要求模型回答问题，而其他提示则强调模型的专业性或应选择最佳答案。

图 13 展示了我们对模型性能在标签变体（左）和 few-shot 标签偏差（右）方面的鲁棒性实验结果。结果表明，我们的预训练语言模型对 MCQ 标签的变化和 few-shot 提示标签的结构非常鲁棒。这种鲁棒性在 405B 参数模型中尤为显著。图 14 展示了我们对答案顺序和提示格式鲁棒性的研究结果。图中的结果进一步强调了预训练语言模型性能的鲁棒性，特别是 Llama 3 405B。

5.1.3 对抗性基准

Adversarial Benchmarks

除了上述基准外，我们还在三个领域的多个对抗性基准上进行了评估：问答、数学推理和释义检测。这些测试探测模型在专门设计为具有挑战性的任务上的能力，也可能揭示对基准的过拟合。对于问答，我们使用 Adversarial SQuAD (Jia and Liang, 2017) 和 Dynabench SQuAD (Kiela et al., 2021)。对于数学推理，我们使用 GSM-Plus (Li et al., 2024c)。对于释义检测，我们使用 PAWS (Zhang et al., 2019)。

图 15 展示了 Llama 3 8B、70B 和 405B 在对抗性基准上的得分，以它们在非对抗性基准上的性能为函数。我们使用的非对抗性基准包括：SQuAD (Rajpurkar et al., 2016) 用于问答、GSM8K 用于数学推理、QQP (Wang et al., 2017) 用于释义检测。每个数据点代表一个对抗性数据集与非对抗性数据集的配对（例如 QQP 与 PAWS 配对），我们展示了类别内的所有可能配对。对角线黑线代表对抗性与非对抗性数据集之间的性能均等——位于线上表示模型在对抗性方面具有相似的性能。

在释义检测方面，预训练模型和后训练模型似乎都不受 PAWS 构建方式的对抗性影响，这标志着相比于前代模型的实质性进步。这一结果确认了 Weber et al. (2023a) 的发现，即 LLM 对多个对抗性数据集中发现的虚假相关性不太敏感。然而，对于数学推理和问答，对抗性性能显著低于非对抗性性能。这种模式在预训练模型和后训练模型中相似。

5.1.4 污染分析

Contamination Analysis

我们进行了污染分析，以估计基准得分在多大程度上可能受到评估数据在预训练语料库中污染的影响。先前的工作中使用了多种不同的污染方法，具有不同的超参数——我们参考 Singh et al. (2024) 的综述。这些方法中的任何一种都可能存在假阳性和假阴性，如何最好地进行污染分析目前仍是一个开放的研究领域。本文中，我们主要遵循 Singh et al. (2024) 的建议。

表 15：被认定为污染的评价集百分比及由此产生的估计性能增益（Percentage of evaluation sets considered to be contaminated and the estimated performance gain）。 详情见正文。

方法（Method）. 具体地，Singh et al. (2024) 提出基于哪种方法导致数据集"干净"部分与整个数据集之间的最大差异来经验性地选择污染检测方法，他们称之为估计性能增益。对于所有评估数据集，我们基于 8-gram 重叠对示例进行评分，Singh et al. (2024) 发现该方法对许多数据集是准确的。如果数据集 D 的一个示例中，比例为 TD 的 token 是预训练语料库中至少出现一次的 8-gram 的一部分，则认为该示例被污染。我们为每个数据集单独选择 TD，基于在三种模型规模上哪个值显示出最大的显著估计性能增益。

结果（Results）. 在表 15 中，我们报告了所有关键基准中，按照上述方法，在最大估计性能增益下被认为污染的评价数据百分比。从表中，我们排除了结果不显著的基准数据，例如因为干净或污染集的示例太少，或者观察到的性能增益估计表现出极端不稳定的行为。在表 15 中，我们观察到对于某些数据集，污染具有较大影响，而对其他数据集则不然。例如，对于 PiQA 和 HellaSwag，污染估计和性能增益估计都较高。而对于 Natural Questions，估计的 52% 污染似乎对性能几乎没有影响。对于 SQuAD 和 MATH，低阈值产生高污染水平，但没有性能增益。这表明对这些数据集来说，污染要么没有帮助，要么需要更大的 n 来获得更好的估计。最后，对于 MBPP、HumanEval、MMLU 和 MMLU-Pro，可能需要其他污染检测方法：即使使用更高的阈值，8-gram 重叠给出的污染分数仍然很高，以至于无法获得良好的性能增益估计。

5.3 人工评估

Human Evaluations

除了标准基准集的评估外，我们还进行了一系列人工评估。这些评估使我们能够衡量和优化模型性能的更细微方面，例如模型的语气、冗长度以及对细微差别和文化背景的理解。设计良好的人工评估能够紧密反映用户体验，提供模型在真实场景中表现的洞察。

提示收集（Prompt collection）. 我们收集了涵盖广泛类别和难度的高质量提示。为此，我们首先开发了一个包含类别和子类别的分类体系，尽可能多地涵盖模型能力。我们使用这个分类体系收集了约 7,000 个提示，涵盖六种单轮能力（英语、推理、编码、印地语、西班牙语和葡萄牙语）和三种多轮能力¹¹（英语、推理和编码）。我们确保在每个类别内，提示均匀分布于各子类别。我们还将每个提示分为三个难度级别之一，并确保提示集合在各个类别和难度上具有代表性。

提示词收集（Prompt collection）。我们收集了涵盖广泛类别和难度的高质量提示词。为此，我们首先开发了一套分类体系，包含各类别和子类别，以尽可能覆盖更多的模型能力。我们使用这套分类体系收集了约 7,000 条提示词，覆盖六种单项能力（英语、推理、编程、印地语、西班牙语和葡萄牙语），以及三种多轮能力¹¹（英语、推理和编程）。我们确保在每个类别内，提示词在各个子类别中均匀分布。我们还将每条提示词划分为三个难度等级之一，并确保我们的提示词集合大致包含 10% 简单提示词、30% 中等提示词和 60% 困难提示词。所有人工评估提示词集都经过了严格的质量保证流程。建模团队无法访问我们的人工评估提示词，以防止意外污染或对测试集过拟合。

¹¹对于多轮人工评估，每个提示的轮数在 2 到 11 之间。我们评估模型在最后一轮中的响应。

Evaluation process. 评估过程。为了对两个模型进行成对人工评估，我们要求人工标注者比较两个模型生成的回复（由不同模型生成），并选择其更偏好的一方。标注者使用7分量表进行评分，从而能够表明一个模型的回复比另一个模型的回复是"好很多"、"更好"、"略好"还是"差不多"。当标注者指出一个模型的回复比另一个模型的回复"更好"或"好很多"时，我们将其视为该模型的"获胜"。我们在模型之间进行成对比较，并按提示集中的能力报告胜率。

Results. 结果。我们使用人工评估流程将 Llama 3 405B 与 GPT-4（0125 API版本）、GPT-4o（API版本）和 Claude 3.5 Sonnet（API版本）进行比较。这些评估的结果如图17所示。我们观察到 Llama 3 405B 的表现与 GPT-4（0125 API版本）大致相当，而与 GPT-4o 和 Claude 3.5 Sonnet 相比则结果参差不齐（有赢有输）。在几乎所有能力上，Llama 3 和 GPT-4 的胜率都在误差范围内。在多轮推理和编码任务上，Llama 3 405B 优于 GPT-4，但在多语言（印地语、西班牙语和葡萄牙语）提示上落后于 GPT-4。Llama 3 在英文提示上与 GPT-4o 持平，在多语言提示上与 Claude 3.5 Sonnet 持平，在单轮和多轮英文提示上优于 Claude 3.5 Sonnet。然而，它在编码和推理等能力上落后于 Claude 3.5 Sonnet。从定性角度看，我们发现模型在人工评估中的表现受到模型语气、回复结构和冗长度等细微因素的强烈影响——这些正是我们在后训练过程中优化的因素。总体而言，我们的人工评估结果与标准基准评估结果一致：Llama 3 405B 与领先行业模型具有很强的竞争力，使其成为性能最佳的开放可用的模型。

Limitations. 局限性。所有人工评估结果都经过了严格的数据质量保证流程。然而，由于为评估模型回复定义客观标准颇具挑战性，人工评估仍可能受到人工标注者个人偏见、背景和偏好的影响，这可能导致结果不一致或不可靠。

5.4.2 安全预训练

Safety Pre-training

我们坚信，负责任的开发必须从端到端的视角来考虑，并融入模型开发和部署的每个阶段。在预训练期间，我们应用了各种过滤器，例如识别可能包含个人身份信息的网站的过滤器（参见第3.1节）。我们还重点关注可发现的记忆化（Nasr et al., 2023）。与 Carlini et al.（2022）类似，我们使用高效的滚动哈希索引对语料库中所有 n-gram （滑动，重叠）进行采样，以不同频率出现的提示和真实数据作为采样依据。我们通过改变提示和真实数据的长度、目标数据的检测语言以及领域来构建不同的测试场景。然后，我们测量模型逐字生成真实数据序列的频率，并分析指定场景下的相对记忆率。我们将逐字记忆定义为包含率（Inclusion Rate）——即模型生成的回复中精确包含真实数据延续部分的比例——并按数据中给定特征的普遍性加权报告平均值，如表24所示。我们发现训练数据的记忆率较低（405B 模型在 n=50 和 n=1000 时平均分别为 1.13% 和 3.91%）。记忆率大致与 Llama 2 在相同规模和使用相同方法对其数据混合进行评估的水平相当。¹²

5.4.3 安全微调

Safety Finetuning

我们描述了我们用于缓解多种能力风险的安全微调方法，涵盖两个关键方面：(1) 安全训练数据；(2) 风险缓解技术。我们的安全微调流程建立在通用微调方法之上，并进行了针对特定安全问题的修改。我们优化两个主要指标：违反率（Violation Rate, VR），即模型生成违反安全策略的回复的比例；以及假性拒绝率（False Refusal Rate, FRR），即模型错误地拒绝回答无害提示的比例。同时，我们在有用性基准上评估模型性能，以确保安全改进不会损害整体有用性。

图18 模型大小对安全混合设计的影响——平衡违反率(VR)和假性拒绝率(FRR)。散点图中的每个点代表不同的安全与有用性数据混合比例。不同规模的模型保留不同的安全学习能力。我们的实验表明，8B模型需要在整体SFT混合中比70B模型使用更高比例的安全数据，才能达到相当的安全性能。更大的模型更能区分对抗性和边界性上下文，从而在VR和FRR之间取得更有利的平衡。

Finetuning data. 微调数据。安全训练数据的质量和设计对性能有着深远的影响。通过大量消融实验，我们发现质量比数量更为关键。我们主要使用从数据供应商处收集的人工生成数据，但发现这些数据容易出错和不一致——尤其是在细微的安全策略方面。为确保最高质量的数据，我们开发了AI辅助标注工具来支持严格的质量保证流程。除了收集对抗性提示外，我们还收集了一组相似提示，我们称之为边界性提示（Borderline Prompts）。这些提示与对抗性提示密切相关，但目标在于教会模型提供有帮助的回复，从而降低假性拒绝率（FRR）。除人工标注外，我们还利用合成数据来提高训练数据集的质量和覆盖率。我们采用一系列技术来生成额外的对抗性示例，包括使用精心设计的系统提示进行上下文学习、基于新攻击向量的种子提示引导变异，以及包括 Rainbow Teaming（Samvelyan et al., 2024）在内的先进算法，该算法基于 MAP-Elites（Mouret and Clune, 2015），能够生成在多个多样性维度上受到约束的提示。

个人注： “边界性提示”指的是那些表面看起来可能有风险，但实际意图是良性的提示词。

我们进一步调整了模型在生成安全回复时的语气，这对下游用户体验有影响。我们为 Llama 3 制定了拒绝语气指南，并通过严格的质量保证流程确保所有新的安全数据都符合该指南。我们还通过零样本重写和人在回路编辑相结合的方式，对现有安全数据进行优化以符合该指南，从而生成高质量数据。通过采用这些方法，并结合用于评估安全回复语气质量的语气分类器，我们能够显著改善模型的措辞。

Safety supervised finetuning. 安全监督微调。遵循 Llama 2 的方案（Touvron et al., 2023b），我们在模型对齐阶段将所有有用性数据和安全性数据合并。此外，我们引入了边界性数据集，帮助模型区分安全和不安全请求之间的微妙差异。我们的标注团队按照指南精心制作安全提示的回复。我们发现，当我们在策略上平衡对抗性和边界性示例的比例时，SFT 在模型对齐方面非常有效。我们将重点放在更具挑战性的风险领域，使用更高比例的边界性示例。这在保持极低的假性拒绝率的同时，对我们的安全缓解工作的成功起到了关键作用。此外，我们在图18中考察了模型大小对 FRR 和 VR 之间权衡的影响。我们的结果显示，这种情况因模型而异——较小的模型需要相对于有用性数据使用更大比例的安全数据，并且与较大的模型相比，更难有效地平衡 VR 和 FRR。

Safety DPO. 安全DPO。为了强化安全学习，我们将对抗性和边界性示例纳入 DPO 的偏好数据集中。我们发现，构建在嵌入空间中近似正交的回复对，对于教会模型区分给定提示下的好回复和坏回复特别有效。我们进行了多次实验，以确定对抗性、边界性和有用性示例的最佳比例，旨在优化 FRR 和 VR 之间的权衡。我们还发现模型大小会影响学习效果——因此，我们为不同规模的模型定制了不同的安全数据混合方案。

虽然低违反率是可取的，但将假性拒绝作为对抗指标来考虑至关重要，因为一个总是拒绝的模型是最安全的，但也毫无有用性可言。同样，一个无论请求多么有问题都始终回答每个提示的模型将过于有害和具有毒性。在图21中，利用我们的内部基准，我们探索了行业中不同模型和系统如何应对这一权衡，以及 Llama 3 的对比情况。我们发现，我们的模型在保持较低假性拒绝率的同时，实现了非常有竞争力的违反率指标，表明在有用性和安全性之间取得了良好的平衡。

Multilingual safety. 多语言安全。我们的实验表明，英文的安全知识并不能轻易迁移到其他语言，尤其是在安全策略的细微差别和语言特定语境方面。因此，为每种语言收集高质量的安全数据至关重要。我们还发现，每种语言的安全数据分布从安全角度显著影响性能，有些语言受益于迁移学习，而其他语言则需要更多特定语言的数据。为了实现 FRR 和 VR 之间的平衡，我们迭代地添加对抗性和边界性数据，同时监控对两个指标的影响。

我们在图19中展示了短上下文模型的内部基准结果，显示了 Llama 3 在英文和非英文语言上的违反率和假性拒绝率，并与类似模型和系统进行了比较。为每种语言构建基准时，我们使用了母语者编写的提示，有时还辅以从英文基准翻译而来的提示。对于我们支持的每种语言，我们发现，在我们内部基准上测量的结果中，带有 Llama Guard 的 Llama 405B 至少与两个竞品系统一样安全（如果不更安全的话），同时保持了有竞争力的假性拒绝率。单独看 Llama 405B 模型（不带 Llama Guard），我们发现其违反率显著低于竞品的独立开源模型，但代价是假性拒绝率较高。

Long-context safety. 长上下文安全。长上下文模型容易受到多轮越狱攻击，如果没有针对性的缓解措施（Anil et al., 2024）。为解决这一问题，我们在 SFT 数据集中加入了包含上下文中有不安全行为示范时仍保持安全行为的示例，并在此基础上对模型进行微调。我们开发了一种可扩展的缓解策略，显著降低了 VR，有效抵消了长上下文攻击（即使对于 256-shot 攻击）的影响。这种方法对 FRR 和大多数有用性指标几乎没有影响。

个人注：多轮越狱攻击

当模型支持很长的上下文（能记住很多轮对话）时，攻击者可以通过多轮对话，把恶意意图拆散、隐藏、逐步铺垫，最终绕过模型的安全防护，让它输出本该拒绝的内容。

为量化我们的长上下文安全缓解措施的有效性，我们使用了两种额外的基准测试方法：DocQA 和 Many-shot。DocQA（文档问答）使用包含可能被恶意利用的信息的长文档。模型同时获得文档和一组与文档相关的提示，以测试与文档信息相关的问题是否影响了模型安全回复提示的能力。Many-shot 遵循 Anil et al.（2024）的方法，我们构建了一个由不安全的提示-回复对组成的合成聊天历史。使用一个与之前消息无关的最终提示，测试上下文中的不安全行为是否影响了模型做出不安全回复。DocQA 和 Many-shot 的违反率和假性拒绝率如图20所示。我们看到，无论是在 DocQA 还是 Many-shot 上，Llama 405B（带和不带 Llama Guard）在违反率和假性拒绝率方面都 Pareto 优于 Comp. 2 系统。相对于 Comp. 1，我们发现 Llama 405B 显著更安全，但在假性拒绝方面有所权衡。

Tool usage safety. 工具使用安全。可能的工具的多样性以及工具使用调用和集成到模型中的实现方式，使得工具使用成为一个难以完全缓解的能力（Wallace et al., 2024）。我们重点研究了搜索用例。违反率和假性拒绝率如图20所示。我们与 Comp. 1 系统进行了测试对比，发现 Llama 405B 显著更安全，尽管假性拒绝率略高。

Uplift testing for chemical and biological weapons. 化学和生物武器提升测试。为评估与化学和生物武器扩散相关的风险，我们进行了提升测试，旨在评估使用 Llama 3 是否可能显著增强行为者策划此类攻击的能力。

该研究包含六小时场景，由两人组成的团队被要求为生物或化学攻击制定虚构的操作计划。这些场景涵盖了 CBRNE 攻击的主要规划阶段（制剂获取、生产、武器化和投送），旨在引出详细的计划，以应对受限材料采购、真实实验室方案和行动安全方面的挑战。参与者根据其在相关科学或操作领域的先前经验进行招募，并被分配到由两名低技能（无正式培训）或两名中等技能（在科学或操作方面有一定正式培训和实践经验）组成的团队。

该研究是与一组 CBRNE 专家合作生成的，旨在最大化定量和定性结果的普适性、有效性和稳健性。我们还进行了初步研究以验证研究设计，包括稳健的功效分析，确保样本量足以进行统计分析。

每个团队被分配到"对照组"或"LLM 组"。对照组团队仅可访问基于互联网的资源，而 LLM 组团队除互联网访问外，还可使用 Llama 3 模型（配备网络搜索（含 PDF 提取）、信息检索能力（RAG）和代码执行（Python 和 Wolfram Alpha））。为测试 RAG 能力，使用关键词搜索生成了包含数百篇相关科学论文的数据集，并预加载到 Llama 3 模型推理系统中。演练结束后，由具有生物学、化学和作战规划领域专业知识的主题专家对每个团队生成的操作计划进行评估。每个计划在潜在攻击的四个阶段进行评估，生成科学性、细节、规避检测以及科学和操作执行成功率等方面的评分。经过稳健的 Delphi 过程以减轻主题专家（SME）评估中的偏见和变异性，最终分数通过汇总各阶段指标生成综合评分。

对这些研究结果的定量分析显示，使用 Llama 3 模型在性能上没有显著提升。这一结果在汇总分析（比较所有 LLM 组与仅限网络对照组）以及按亚组进行分析时（例如，分别评估 Llama 3 70B 和 Llama 3 405B 模型，或分别评估与化学或生物武器相关的场景）均成立。在通过 CBRNE SME 验证这些结果后，我们评估认为，发布 Llama 3 模型将增加与生物或化学武器攻击相关的生态系统风险的可能性较低。

5.4.6 红队测试

Red Teaming

我们利用红队测试来发现风险，并将发现结果用于改进我们的基准和安全调优数据集。我们进行定期的红队测试，以持续迭代并发现新的风险，这指导着我们的模型开发和缓解过程。

我们的红队由网络安全、对抗性机器学习、负责任AI和诚信领域的专家组成，此外还有具备特定地理市场诚信问题背景的多语言内容专家。我们还与关键风险领域的内部和外部主题专家合作，帮助构建风险分类法，并协助进行更有针对性的对抗性评估。

特定模型能力的对抗性测试。 对特定模型能力的对抗性测试。我们首先通过关注个别模型能力进行风险发现过程中的初始红队测试，在特定高风险类别的背景下，然后测试能力组合。红队专注于提示级攻击，以模拟更接近真实世界的场景——我们发现模型经常偏离预期行为，尤其是在提示意图被模糊化或提示包含多层抽象的情况下。随着能力的增加，这些风险变得更加复杂，我们将在下面详细描述我们的几个红队发现。我们将这些红队发现与我们的内部安全基准结果相结合，以开发有针对性的缓解措施，持续迭代地提高模型安全性。

  • 短上下文和长上下文英文。我们采用了单轮和多轮对话中一系列已知的、已发表和未发表的技术。我们还利用了一些技术（如 PAIR，Chao et al., 2023）和风险类别的高级对抗性多轮自动化。在多轮对话中，很大程度上会导致更有害的输出。几种攻击在模型检查点中普遍存在，尤其是在组合使用时。
    • 多轮拒绝压制：指定模型回复遵循特定格式，或包含/排除与拒绝相关的特定短语作为特定信息。
    • 假设场景：将违规提示包装为假设性/理论性任务或虚构场景。提示可以简单到添加"假设"一词，或精心设计一个复杂的多层场景。
    • 角色扮演：赋予模型一个违规的角色，具有特定的违规回复特征（例如"你是X，你的目标是Y"），或用户自身采用特定的良性角色以模糊提示的上下文。
    • 添加免责声明和警告：作为一种回复启动形式，我们假定这是一种让模型走向有用遵从的路径，与通用安全训练相交织。在多轮对话中要求添加免责声明、触发警告等，结合其他提到的攻击，导致违反率上升。
    • 逐步升级的违规：这是一种多轮攻击，对话从一个或多或少的良性请求开始，然后通过直接提示要求更夸张的内容，逐步引导模型生成非常违规的回复。一旦模型开始输出违规内容，模型就很难恢复（或者如果遇到拒绝，可以使用另一种攻击）。对于长上下文模型，这将成为一个日益严重的问题。
  • 多语言。我们在考虑多种语言时识别出若干独特风险。
    • 在单个提示或对话中混合多种语言：比使用单一语言更容易导致违规输出。
    • 低资源语言：由于缺乏相关的安全微调数据、模型安全泛化能力弱，或测试/基准的优先级问题，可能导致违规输出。然而，这种攻击通常会导致输出质量普遍较差，限制了实际的对抗性使用。
    • 俚语、特定语境或文化特定引用：乍看之下可能令人困惑或看似违规，但结果是模型未能正确理解给定引用，其输出并不真正有害或不足以构成违规输出。
  • 工具使用。在测试过程中，除了英文文本级别的对抗性提示技术能够成功生成违规输出外，还发现了若干特定于工具的攻击。这包括但不限于：
    • 不安全的工具链式调用：例如同时请求多个工具，其中一个是违规的，在早期的检查点中可能导致所有工具被调用，输入混合了良性和违规内容。
    • 强制工具使用：通常使用特定的输入字符串、分段或编码文本，可能触发工具输入变成潜在违规，从而导致更违规的输出。然后可以使用其他技术来访问工具结果，即使模型通常会拒绝执行搜索或协助处理结果。
    • 修改工具使用参数：例如在查询中替换词语、重试或在多轮对话中模糊部分初始请求，在许多早期检查点中作为一种强制工具使用的方式导致违规。

Child safety risks. 儿童安全风险。儿童安全风险评估由一个专家团队进行，以评估模型产生可能导致儿童安全风险的输出的能力，并为通过微调进行必要和适当的风险缓解提供信息。我们利用这些专家红队会议，在模型开发过程中扩展了评估基准的覆盖范围。对于 Llama 3，我们使用了基于目标的方法进行了新的深入会议，以评估模型在多个攻击向量上的风险。我们还与内容专家合作，进行了红队测试，评估潜在的违规内容，同时考虑市场特定的细微差别或经验。

5.4.7 系统级安全

System Level Safety

在大语言模型的各种实际应用中，模型并非孤立使用，而是集成到更广泛的系统中。在本节中，我们描述我们的系统级安全实现，它通过提供更大的灵活性和控制来补充模型级的缓解措施。

为实现这一点，我们开发并发布了一个新的分类器——Llama Guard 3，这是一个针对安全分类进行微调的 Llama 3 8B 模型。与 Llama Guard 2（Llama-Team, 2024）类似，该分类器用于检测输入提示和/或语言模型生成的输出回复是否违反了特定危害类别的安全策略。

它旨在支持 Llama 不断增强的能力，可用于英文和多语言文本。它还针对工具调用（如搜索工具）和防止代码解释器滥用的上下文进行了优化。最后，我们还提供了量化变体以减少内存需求。我们鼓励开发者以我们发布的系统安全组件为基础，并根据自己的用例进行配置。

Taxonomy. 分类法。我们基于 AI 安全分类法（Vidgen et al., 2024）中列出的13个危害类别进行训练：儿童性剥削、诽谤、选举、仇恨、大规模杀伤性武器、知识产权、非暴力犯罪、隐私、性相关犯罪、色情内容、专业建议、自杀与自残以及暴力犯罪。我们还针对代码解释器滥用类别进行训练，以支持工具调用用例。

Training data. 训练数据。我们从 Llama Guard 使用的英文数据（Inan et al., 2023）开始，并将该数据集扩展到包含新能力。对于多语言和工具使用等新能力，我们收集了提示和回复分类数据，并利用了为安全微调收集的数据。我们通过提示工程使 LLM 不拒绝回答对抗性提示，从而增加训练集中不安全回复的数量。我们使用 Llama 3 获取此类生成数据的回复标签。

为提高 Llama Guard 3 的性能，我们使用人工标注和 Llama 3 LLM 标注对收集的样本进行了大量清洗。获取用户提示的标签对人工和 LLM 都是一项更困难的任务，我们发现人工标签略好，尤其是对于边界性提示，尽管我们完整的迭代系统能够减少噪声并产生更准确的标签。

Prompt-based system guards. 基于提示的系统防护。系统级安全组件使开发者能够自定义和控制 LLM 系统如何响应用户请求。作为我们提高模型系统整体安全性和使开发者能够负责任地部署的工作的一部分，我们描述并发布了两种基于提示的过滤机制的创建：Prompt Guard 和 Code Shield。我们将这些机制开源，供社区按原样使用，或作为灵感并根据自己的用例进行调整。

Prompt Guard 是一种基于模型的过滤器，旨在检测提示攻击，即旨在颠覆作为应用一部分运行的 LLM 预期行为的输入字符串。该模型是一个多标签分类器，可检测两类提示攻击风险——直接越狱（明确试图覆盖模型安全条件设定或系统提示的技术）和间接提示注入（模型上下文窗口中包含的第三方数据含有被 LLM 无意中作为用户指令执行的指令的情况）。该模型基于 mDeBERTa-v3-base 微调而成，这是一个小型的（86M 参数）模型，适用于过滤 LLM 的输入。我们在多个评估数据集上评估了其性能，如表28所示。我们在两个数据集（越狱和注入）上进行评估，这些数据集来自与训练数据相同的分布，此外还有一个英文的分布外数据集、一个基于机器翻译构建的多语言越狱集，以及一个来自 CyberSecEval（英文和多语言）的间接注入数据集。总体而言，我们发现模型能够很好地泛化到新的分布，并具有强大的性能。

Code Shield 是一类基于推理时过滤的系统级保护的一个示例。具体来说，它专注于在生成的不安全代码进入下游用例（如生产系统）之前进行检测。它通过利用静态分析库——不安全代码检测器（Insecure Code Detector, ICD）来识别不安全代码。ICD 使用一套静态分析工具，跨 7 种编程语言进行分析。这类防护措施通常对开发者很有用，他们可以在各种应用中部署多层保护。

5.4.8 局限性

我们对 Llama 3 安全使用所面临的各类风险进行了广泛的测量和缓解。然而，没有任何测试能保证穷尽地识别出所有可能的风险。由于在各种数据集上训练，Llama 3 仍可能生成有害内容，尤其是在英语之外的语言中，以及在被熟练的对抗性红队人员精心设计提示时。恶意开发者或对抗性用户可能会找到新的方法越狱我们的模型，并将其用于各种邪恶用途。我们将继续主动识别风险、开展缓解方法研究，并鼓励开发者在每一个环节都考虑责任——从模型开发到部署再到用户。我们希望开发者能利用并贡献于我们在开源系统级安全套件中发布的工具。
